# 源代码导览

> 给第一次接触本仓库的人：10 分钟看懂代码在哪、从哪读起。

## 从哪开始读

1. `README.md` — 项目是什么、怎么跑。
2. `src/main.js` — 应用怎么启动。
3. `src/router.js` — 有哪些页面。
4. `src/fsrs.js` — 最核心的算法（记忆调度）。
5. `src/repo.js` — 数据怎么读写。
6. `src/agent/orchestrator.js` — AI 怎么工作。

## 代码地图

```
入口与路由        main.js / App.vue / router.js
数据库            db.js（schema） → repo.js / repo-core.js / word-repo.js
算法              fsrs.js + algorithms/（图谱/错题/预测）
AI                agent/orchestrator.js + agent/tools/ + agent/agents/
界面              views/（48 页） + components/ + stores/
同步              sync.js / sync-manifest.js
文档              docs-suite/（本套文档）
测试              tests/*.test.mjs（与源码同名对应）
```

## 读代码的三个约定

1. **业务数据只在 repo 层碰 Dexie**。想看"怎么存卡片"，去 repo.js，不要去 views 里翻 Dexie 调用。
2. **算法是纯函数**。fsrs.js、algorithms/ 里的函数不依赖 DOM，输入数据返回结果——照着测试用例读最快。
3. **AI 工具是注册表模式**。想知道 AI 能干什么，去 `agent/tools/index.js` 按 name 找；想加新能力，照着注册一个。

## 测试怎么对应

- `tests/` 下的测试文件与源码模块基本同名。
- 改了 `fsrs.js`，就先跑 `fsrs` 相关测试。
- 整体 `npm test`。

## 关键文件行数（参考）

- `agent/tools/index.js`：工具注册表，~1000 行。
- `repo.js`：业务 CRUD 主入口。
- `fsrs.js`：调度核心。
- 最大视图：WordBook.vue / Cards.vue / Review.vue。
