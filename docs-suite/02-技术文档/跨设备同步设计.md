# 跨设备同步设计

## 1. 目标

用户在手机和电脑上都能学，进度、卡片、图谱要能汇合，且：
- 编辑不互相覆盖（我改正面、你改背面，两边都要留着）。
- 删除能传播（这边删了，那边别复活）。
- 不依赖商用云服务器。

## 2. 两条通道

1. **局域网同步中枢（sync-hub/）**：一个 Node 小服务，两台设备在同一网络下互通，走本地地址，不出网。
2. **JSON 导入导出**：把全量数据打包成 JSON 文件，手动传到另一台设备导入（无网络时也能用）。

## 3. 合并协议：双时间戳 + LWW + 墓碑

- **字段级时间戳**：每个可编辑字段记自己的 lastModified。两台设备改不同字段，合并后两字段都保留。
- **同字段冲突**：LWW（last-write-wins，时间戳新的赢）。
- **时间戳相同（同毫秒写）**：用确定性 tiebreaker——内容多者赢，再平保持本地，保证两端合并结果一致，不会"这边 A 赢、那边 B 赢"导致同步振荡。
- **墓碑**：删除不是真删，而是写一条"已删除"记录（带时间戳）。合并时墓碑压过任何数据复活。向量块、图谱边都有对应墓碑，防止"删了资料，向量检索又搜出幽灵片段"。

## 4. 原子性

- 删除/修改一张卡牵连多张表（复习记录、分组、图谱边、向量块、墓碑）时，全部包在**一个 IndexedDB 事务**里：要么全成功，要么全回滚，不会留下"删了一半"。
- 原文件（OPFS 里的 Blob，可能几百 MB）单独异步释放，不放进事务（IndexedDB 事务遇 await 会自动提交）。

## 5. 同步状态可观测

sync-status.js 记录待同步/已同步/失败；UI 在"同步"页展示状态，出错可导出反馈日志。
