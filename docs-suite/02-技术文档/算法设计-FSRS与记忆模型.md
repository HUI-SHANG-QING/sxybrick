# 算法设计：FSRS 间隔重复与记忆模型

> 这是本项目最核心、最适合写进论文的技术贡献。

## 1. 问题：为什么不用固定艾宾浩斯

传统复习安排是"第 1/2/7/15 天"这种固定表，对所有人一刀切。但每个人、每张卡的记忆衰减速度不同：有的概念看一眼就记住一个月，有的三天就忘。**真正合理的间隔，应该由"这张卡对你这个人衰减多快"来决定。**

## 2. FSRS 记忆模型

FSRS（Free Spaced Repetition Scheduler）是当前开源记忆软件界的先进调度算法。核心是两个状态量：

- **稳定度 S（stability）**：记忆的牢固程度，单位天。S 越大，忘得越慢。
- **难度 D（difficulty）**：这张卡有多难。

在时间 `t` 天后，你对这张卡的**记忆保持率**为：

```
R(t) = (1 + t / (9·S)) ^ (-1)
```

含义：
- S 越大 → R(t) 掉得越慢（还记得久）。
- t 越大 → R(t) 越低（越往后忘得越多）。

系统设定一个**目标保持率**（默认 0.9，即希望你复习时 90% 还记得）。于是反解出下次复习间隔：

```
下次间隔 t*  ≈ 9·S · (1/0.9 - 1)
```

也就是：**在你"刚好快忘到 90%"的那一刻，安排你复习**。

## 3. 一次复习发生了什么（scheduling）

用户复习一张卡时给一个评分（again/hard/good/easy，对应完全想不起~秒答）。系统据此更新 S 和 D：

- **答对且本来就熟** → S 变大（间隔拉长，下次一周/一月后再来）。
- **答错/想不起** → S 变小、D 变大（间隔骤缩，几天后重学）。

实现里有**护栏**：稳定度封顶、难度有界、梯度训练参数双界钳制，防止一次误操作让间隔算出天文数字。

## 4. 权重训练（个性化）

FSRS 有 19 个参数权重。系统不直接用默认值，而是**用你自己的历史复习记录，用有限差分梯度下降拟合这 19 个权重**，让模型越来越贴合你个人的遗忘节奏。

## 5. 校准回测（calibration）

光训练不算完，要验证"模型说得准不准"。系统把历史记录拿回来：模型当时预测的保持率 vs 你实际答对的比例，分桶统计：

- **Brier 分数**：预测概率与实际对错的均方误差（越小越好）。
- **ECE（期望校准误差）**：预测说"80% 记得"的那批卡，实际是不是真的 80% 答对。
- **偏差**：模型整体偏乐观还是偏悲观。

## 6. 到期洪峰预测（forecast）

容量规划：未来 30 天每天会有多少卡到期？系统模拟每张卡"按 rating 复习后再次到期"的推进过程，输出每天到期量、峰值日、平均负载，并处理了"当天亚日级重学"导致的死循环（最小推进量护栏 + 同日重学上限）。

## 7. 围绕记忆模型的上层算法

| 算法 | 作用 |
|---|---|
| 错题归因 mistakeAttribution | TF-IDF 把反复错的卡按概念聚成簇，找出"你总在同一类知识点上栽" |
| 前置依赖图 graphAuto/prereq | 从标签共现、错题同现推导卡片间前置关系；复习某卡前自动把它的前置卡排前面 |
| 易混对 getConfusablePairs | 同科目、共享标签、双方都错过的卡，配对复习抗混淆 |
| 到期预测 forecastDue | 洪峰预测，提醒"下周三有 200 张要复习，提前安排" |

## 8. 工程上怎么保证算法正确

- 所有算法都是**纯函数、零 DOM、零网络**，直接在 Node 单测。
- 边界全覆盖：空库、单条记录、评分越界、dueAt=0 脏数据、同毫秒时间戳，都有专门用例。
- 数值护栏：稳定度封顶、难度有界、概率钳在 [0,1]、防除零。
- 1079 项测试里，算法相关占大头。
