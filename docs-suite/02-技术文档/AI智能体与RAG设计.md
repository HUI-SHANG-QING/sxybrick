# AI 智能体与 RAG 设计

## 1. 为什么要做"智能体"而不是一个聊天框

普通 AI 问答的问题是：它不知道你库里有什么。你问"我线代哪里弱"，它只能泛泛而谈。
SxyBrick 让 AI **能调用工具去查你真实的数据**——你的卡片、你的复习记录、你的错题，再据此回答。这就是 ReAct（推理+行动）智能体。

## 2. ReAct 循环（orchestrator / pipeline）

用户提问后，编排器循环：

```
思考(该干什么) → 选一个工具 → 执行(查真实数据) → 观察结果 → 再思考 → ...
直到答案足够 → 总结成自然语言
```

- 每个工具声明它是 `readsData`（只读）还是 `writesData`（会写库）。
- 40+ 工具：get_stats / search_cards / create_card / quiz_me / semantic_search / link_cards / calibration_report ……
- 加新工具只要在 registry 注册，不改编排器（开闭原则）。

## 3. 十个智能体

每个智能体有独立 system prompt，专长一个领域：

| 智能体 | 干什么 |
|---|---|
| tutor 导师 | 结合你的卡片讲解概念 |
| analyst 分析师 | 学习数据/薄弱点分析 |
| cardsmith 制卡师 | 把内容拆成高质量卡片 |
| quizmaster 出题官 | 出题测验 |
| planner 规划师 | 排学习计划 |
| memory 记忆管家 | 记忆口诀 |
| mnemonist 助记师 | 联想记忆法 |
| mistake-analyst 错题分析师 | 错题归因 |
| graph-builder 图谱构建 | 建知识关系 |
| smart-reviewer 智能复习官 | 编排复习顺序 |

智能体之间可以 `delegate_to_agent` 互相委托；协作模式下通过**黑板 blackboard** 共享发现与产出。

## 4. RAG 检索（retrieval + embedding）

用户问"我有没有学过特征工程"时：

1. 把问题向量化（embedding）。
2. 在本地卡片/文档的向量库里算余弦相似度。
3. **混合打分**：语义相似度 × 0.65 + 关键词匹配 × 0.35，取 top-k。
4. 把命中的卡片片段塞进 AI 的上下文，让它基于这些真实材料回答，而不是瞎编。

**关键工程点——降级与一致性**：
- 远程 embedding API 失败时，自动降级到本地小模型；此时数据落库的模型签名会标记为 `local:fallback`，等远程恢复后签名不匹配、自动触发重建，避免"1536 维查询 vs 256 维存量"永远搜不到的问题。
- 索引增量更新（ensureIndex）只处理新增/变更卡，不全量重建。

## 5. 多智能体黑板（blackboard）

流水线模式下：多个智能体并行开工，各自把"发现(finding)"和"结构化产出(artifact)"写到共享黑板，别的智能体能读别人的成果继续干活，最后汇总。

## 6. 长期记忆（memory）

跨会话记住你的偏好：分三层——核心记忆、偏好、事实，各有条数上限，避免无限膨胀；写墓碑、事务化，同步时不丢。

## 7. 可靠性兜底（重点，答辩可讲）

- **local-answer**：工具已经查到数据了，但"把数据总结成话"那一步 LLM 挂了（无网/无 Key），系统用确定性模板把结构化数据渲染成 Markdown，**至少让你看到真实结果，不白跑一趟**。
- **proactive 主动建议**：定时/切回前台时轻量检查"该不该提醒"，带并发互斥，不会重复推送同一条。
- **敏感词/注入**：工具结果回显走 DOMPurify 净化；AI 返回的结构化结果有渲染出口兜底，不会把裸 JSON 直接吐给用户。

## 8. 隐私口径

- AI 调用用**用户自己填的 API Key**，存在 localStorage。
- 学习内容（卡片/对话）不经过任何官方服务器；RAG 检索发生在本地或经用户同意后才发往用户自己的模型端点。
