# 开发规范

## 1. 技术栈（必须遵循）

- 框架：Vue 3（组合式 API）+ Vite 6 + Pinia + Vue Router。
- UI：Element Plus + ECharts + KaTeX。
- 存储：Dexie/IndexedDB，不绕过 repo 层直接写裸查询。
- 语言：ES Module；纯算法必须零 DOM、零网络依赖（保证 Node 可测）。

## 2. 目录纪律

- UI 放 `views/`/`components/`；可复用逻辑放 `composables/`；Pinia 状态放 `stores/`。
- 业务数据访问一律走 `repo*.js`，组件不直接操作 Dexie。
- 纯算法放 `algorithms/`；AI 工具放 `agent/tools/`。

## 3. 提交前自检（强制）

```bash
npm test        # i18n 闸门 + 依赖检查 + 全部测试
npm run lint
npm run build
```
任何一项不通过，不提交。

## 4. 命名与文案

- 所有界面文案走 `src/i18n/` 字典，禁止在 .vue/.js 里写死中文（有 `check-view-i18n.mjs` 自动拦）。
- 变量/函数见名知意；算法函数写清输入输出与边界。

## 5. 算法改动特别要求

- 改 fsrs/检索/同步逻辑，必须补或改测试。
- 数值必须有护栏：概率 [0,1]、防除零、空输入返回空结构。
- 同步合并必须确定性（同输入同输出），不依赖运行时序。

## 6. Git 提交约定

- 提交信息：`<类型>(<范围>): <简述>`，类型如 feat/fix/docs/refactor/test。
- 小步提交，一次只做一件事；不要把格式化和功能改动混在一个提交。
- 推送前确认 `npm test` 全绿。

## 7. 已知环境坑（Windows）

- 工作区文件为 CRLF；脚本做字符串替换前先归一化，写回再还原。
- Windows Defender 可能拦截 `.git/objects`，使用项目提供的 force-add/commit 脚本。
