# SxyBrick 顶级交叉专家全方位评审报告（v2）

> **评审性质**：纯分析、零代码改动。所有结论基于 `new_card/` 真实源码核验（db v14、24 视图、84 源码文件、2 份测试、package.json、sync-manifest、srs、repo、telemetry 等）。
> **评审时间锚点**：2026-08-27。引入一项新事实——开发者自述**本项目由单人全程用 AI 编辑器从零构建仅耗时 3 天、消耗约 7000 额度（≈350 元）**，该事实作为"开发范式"元变量贯穿全文。
> **交叉专家阵容**：软件开发工程师 / 架构设计师 / 算法开发工程师 / 学习·复习领域专家 / 数据资产化专家 / 产品经理 / AI 架构师。

---

## 0. 评审口径与一句话总评

**总评**：SxyBrick 是一个**本地优先 + 记忆科学 + 自研轻量 Agent + 数据主权**四位一体的考研复习操作系统，在"个人知识管理 + 间隔重复"赛道上已达到**准产品级**完成度。其最大资产是**架构纪律**（sync-manifest 单一事实源）与**认知科学落地**（SM-2 变体 + 短期巩固）；最大负债是**测试广度缺失**与**数据治理跑赢隐私合规**（隐私/埋点已进入同步链路但未加密、未设同意闸）。

它不是一个"作业级 Demo"，但也不是"可托付十年的基础设施"——它正处在**"惊艳原型"与"可信长期伴侣"之间的关键跃迁点**。

### 1.1 版本演进（db v1 → v14，全部为 Dexie 版本化迁移）
| 版本 | 新增能力 | 信号意义 |
|---|---|---|
| v1–v6 | cards/reviews/images/tombstones/meta + aiChats/aiMemories/memos/plans/graphEdges/docs/pomoSessions | 复习内核 + 多模块奠基 |
| v7 | mindmaps/weeklyReports/achievements | 借鉴 Progress AI |
| v8 | exams（模考） | 评测闭环 |
| v9 | embeddings（RAG 向量） | AI 检索增强 |

| v11 | errors（本地错误日志） | 运维可观测 |
| v12 | cards.difficulty 索引 | 难度梯度编排 |

**研判**：14 次 schema 演进集中在极短周期内，说明数据模型仍在**高速稳定化**。Dexie 版本化升级机制本身处理得当（向后兼容），但 14 跳迁移对存量用户是持续风险——任何一次迁移逻辑错误都会污染老用户库。

### 1.2 "3 天 AI 构建"的元解读
这是本报告最重要的新变量。它意味：
- **速度真实性**：该开发者对"要什么"有完整终态设计（同步双时间戳、Agent 边界等早已在脑中），AI 只负责落地 → 把"编码量"压缩到近似零。
- **代价（隐性）**：3 天高燃烧（7000 额度）必然伴随**广度优先于深度**——24 视图中多数模块为"可用但浅"；测试、TS、边界加固被牺牲。这是"AI 原生高速开发"的固有权衡，不是缺陷，但必须被**后续刻意清偿**。
- **Bus-factor=1 风险极高**：单人 + AI 的极致效率，意味着知识完全集中在一人脑中，且代码缺乏第二双眼睛的审查（R2 漏网即为例证）。

## 2. 七维顶级专家交叉审视

### 2.1 软件开发工程师视角
**亮点**
- 错误边界 + 本地错误日志（#16，db v11 `errors` 表）是前端应用少有的**运维可观测**实践。
- `telemetry.js` 工程质量高：A/B 两级、去重窗口、批量 `bulkPut`、空闲回调 `requestIdleCallback`、缓冲上限保护内存、触屏设备默认关 B 级——是**生产级埋点采集器**写法。
- 提交历史语义清晰（中文描述、按特性聚合），迭代纪律好。

**硬伤**
- **无 TypeScript**：84 文件、14 表、含复杂算法与 Agent 协议，纯 JS 在可维护性上已逼近拐点；重构时类型安全缺失会放大回归风险。
- **测试广度严重不足（P0）**：仅 `srs.test.mjs` + `sync-manifest.test.mjs` 两份；24 视图、`analytics.js`、`agent/` 全套、同步导出全链路**零测试**。在 3 天高速构建后被放大的代价，正是核心同步 bug 未被捕获。
- **主线程 O(n²) 风险仍在**：`analytics.js` 多模块全表扫描/配对（弱卡、易混对）在千卡级会卡顿，缺乏虚拟化/增量计算。

### 2.2 架构设计师视角
**亮点（教科书级）**
- `sync-manifest.js` 作为**同步唯一事实源**，被浏览器端 `sync.js` 与 Node 端 `hub.js` 共用——从根上消灭"三处合并逻辑漂移"这条分布式同步经典死法。这是全项目**最值钱的设计判断**。
- 五层单向依赖：表现层(Vue+Pinia+PWA) → 业务域(repo/analytics) → 算法(srs/analytics 确定性) → AI(浏览器内 Agent 运行时 + 远程 LLM) → 数据(Dexie + sync-manifest)。视图不直接碰 `db`，只经 `repo/analytics` 取数，解耦干净。

**风险**
- `hub.js`（局域网中继）是**唯一的"服务端"**，非应用后端；它复用 sync-manifest 正确，但作为一个"中枢"缺乏鉴权、配额、并发控制——仅适合可信局域网。
- 算法层多处计算阻塞 UI（见 2.1）；AI 工具执行在主线程，长任务会冻结交互。

### 2.3 算法开发工程师视角（SRS 算法族深度）
`srs.js` 已进化为含 **5 个子系统**的算法族（远超裸 SM-2）：
1. **难度系数** `DIFF_FACTOR=[1.15,1.0,0.8]` 拟合个性化遗忘曲线；
2. **错因惩罚** `wrongPenalty()` 按概念混淆/记忆不牢/粗心分级缩短间隔；
3. **短期巩固状态机**（`consolidation` 1→2→毕业，6h + 隔日双窗口，引用 Roediger & Karpicke 2006）——**认知科学落地正确**；
4. **自适应** 按近 10 次错误率微调（≥40% 缩短 / 全对且等级≥3 拉长）；
5. **强度系数** `intensity` 调节间隔。

**科学性与严谨性评判（B+ → A-）**
- 短期巩固的"24h 内首次主动提取"确为记忆巩固最强窗口，方向站得住。
- **脆弱点**：`wrongPenalty` 用中文字符串 `includes` 模糊匹配（'概念'/'混淆'/'记忆'…），一旦用户措辞偏离即静默失效（惩罚=1.0）。应改为**受控枚举**（结构化错因码）而非自由文本嗅探。
- **"遗忘曲线拟合"名实**：当前只是 `ease^level` 指数间距，并非真正拟合个体遗忘曲线（如 FSRS 的权重回归）。作为启发式可接受，但命名偏营销。
- **算法测试到位**：`srs.test.mjs` 覆盖巩固状态机各转移（12–39 行），是本次评审中为数不多的"测试跟上了算法"之处。

### 2.4 学习·复习领域专家视角（认知科学）
- **已正确实践**：主动回忆（背诵）、测试效应、费曼输出、间隔重复、错题驱动（wrongReason）、易混对决（interleaving）、 desirable difficulties。
- **可深化**：缺乏真正**记忆留存强度模型**（推荐 FSRS——开源、可本地运行、比手调 SM-2 变体更严谨）；短期巩固为固定时间表而非按实际留存校准，个性化上限受限于此。
- **产品化缺口**：已有 `telemetry` 海量行为数据，却**未见"基于真实留存曲线的难度校准"闭环**——埋点未反哺算法参数，是"数据资产"与"算法"两张皮。

### 2.5 数据资产化专家视角（**本次最重要新发现**）
**成熟面（E1/E2/E3 资产框架）**
- E1 保值：体检/去重/全局搜索/对账；
- E2 流转：Anki 互通/卡组署名；
- E3 叙事：书房/个人主题/模考走势。
资产化叙事完整，且坚持**本地私有 + 多通道导出**，真正把数据主权还给用户——理念领先。

**反转风险（R7，P0 级合规负债）**
- `privacyRecords`（db v14）含 **mood/energy/focus/pleasure/stress/painIndex/财务块/精神心流 Markdown**——属《个人信息保护法》**敏感个人信息**（健康、金融、心理状态）。
- 该表**已纳入 `SYNC_TABLES`（merge: updatedAt）**，并随 USB/GitHub Pages/局域网中枢**明文导出与同步**——**无加密-at-rest、无同意闸、无最小化**。

> **核心矛盾**：数据资产化走到极端，反而让"资产"变成" liability"。本地单设备时风险可控；一旦进入同步/导出/未来云端，未治理的敏感人生数据即构成直接合规雷区。这是商业化前**必须先解决的阻断项**。

**机会面**：若把 `privacyRecords` 改为**默认不入同步、本地加密、显式 opt-in**，并以"学习×生活相关性"（如睡眠→留存）作为差异化洞见产品，则数据资产化从负债变护城河。

### 2.6 产品经理视角
- **功能面极宽**：24 视图覆盖学习/复习/错题/费曼/计划/文档/图谱/导图/模考/周报/成就/健康/隐私/书房/仪表盘/同步/导出/搜索/Agent 工作台/AI 助手——典型的"学习+人生一体化 OS"野心。
- **定位张力**：**本地优先 + 数据主权 + AI 教练 + 人生量化**是强差异点，但"什么都做"可能导致**无聚焦**。建议分层：复习内核（留存钩子）为北极星，其余为增值模块。
- **留存闭环设计好**：间隔重复（核心钩子）+ 打卡 streak + 成就 + 周报 + 数字孪生仪表盘，engagement 机制齐备。
- ** irony**：有最豪华的埋点（userOps），却未见"功能激活/漏斗分析"产品化输出——埋点尚未转化为"该砍哪个模块"的决策依据。

### 2.7 AI 架构师视角
- **自研轻量 Agent 框架**：Registry / ReAct / 编排流水线 / 黑板 / 主动智能体 / 离线兜底 / 分层记忆 / 上下文注入 / embedding + retrieval（RAG）/ OpenAI 兼容 LLM 适配——**对纯前端应用而言架构成熟度惊人**。
- LLM 算力在**用户自配远程端点**（DeepSeek 默认），密钥不上客户端代码，隐私边界清晰；`offlineAI.js` 作无网降级，韧性好。
- **关键缺口**：
  - `embeddings` 表**未纳入 `SYNC_TABLES`**（R3 仍存）→ 换设备 RAG 静默失效，需重建索引；
  - `notifications`(v10)、`errors`(v11) 也未在同步清单——需明确"哪些表故意不同步"并文档化；
  - 工具执行阻塞主线程，缺少 Web Worker 隔离。

## 4. 机会登记表（O1–O6）

- **O1 算法-数据闭环**：用 `userOps` 真实留存数据反哺 `srs` 参数（迈向 FSRS 级严谨）。
- **O2 隐私合规即护城河**：把敏感数据改为本地加密 + opt-in，做"学习×生活相关性"洞见，差异化极强。
- **O3 卡组市场网络效应**：E2 流转（署名/Anki 互通）可升级为可交易/订阅资产市场。
- **O4 Agent 框架平移后端**：自研 Agent 协议（文本工具协议、兼容任意端点）可直接平移为服务端 AI 微服务。
- **O5 数字孪生叙事**：Dashboard + userOps + privacyRecords 构成"学习数字孪生"，是独特卖点。
- **O6 本地优先合规红利**：纯本地 + 用户自带密钥，天然规避多数 SaaS 数据合规负担（除 R7 外）。

## 7. 元结论

> SxyBrick 是**"AI 原生高速开发"范式下诞生的准产品级学习操作系统**：它用 3 天、350 元，产出了传统团队数月才能堆出的功能广度与架构纪律，其 sync-manifest 设计与认知科学落地是真正的工程智慧。但它也浓缩了这种范式的全部代价——**测试稀薄、类型缺失、且数据资产化已快过隐私治理**。
>
> 从"惊艳原型"晋级为"可信赖长期伴侣"与"可商业化产品"，关键不在重写，而在**补齐三块短板**：跨设备同步正确性（R2/R3）、敏感数据治理（R7）、测试与类型可维护性。这三件事做对，它的本地优先 + 数据主权 + 自研 Agent 三位一体，足以构成难以复制的护城河。
