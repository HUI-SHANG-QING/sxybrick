# SxyBrick 与同类项目（Progress AI）对比 + 扩展路线

> 调研日期：2026-08-28 ｜ 调研人：Senior Developer + 公开学术研究
> 对标项目：http://localhost:3000/ (Vue3+ElementPlus+i18n+云端后端，PWA，「Progress AI」)
> 用户明示优先级：监督力效率（防「耍起来」）> 学习闭环 > 思维/笔记 > UX

---

## 0. 关键结论（TL;DR）

1. **Priority-0（最高杠杆 = 监督力）**：基于 Kirchner-Krath(2025) 与 Lee(2024) 研究——
   *「友善推送对拖延几乎没用，必须**轻微摩擦/负面情绪**才动」*。我们当前所有提示都是「鼓励式」，需要补 **「损失可视化 + 真实紧迫感 + how-to 推送」三类强干预**。
2. **Priority-1**：用户明示三项差距——**自动分类、笔记系统增强、导出（笔记/图谱/资料）**——其中前两项单点实现成本低、用户感知最大。
3. **Priority-2**：同类有但我们缺的——**Benchmark（基准测试）、完整 Exam 闭环（出题→作答→批改→错题本）、学习路径（LearningPath）、白噪音番茄钟**。
4. **Priority-3**：跨域思考的差异化竞争——**链接笔记（RemNote 模式）、费曼学习法强化（已有 selfExplain 字段但 UI 无）、错误模式驱动复习（已有 mistake-analyst agent 但与复习流未深度耦合）**。
5. **不做的（避免范围蔓延）**：多租户/会员/PRO 限制（我们是本地优先 PWA）、多人协作（要先有云后端，路线图暂缓）、手写识别/扫描生词卡（功能宽但与核心学习闭环弱相关）。

## 3. 优先级路线（按杠杆 + 实现成本排序）

### Phase 7 — 学习闭环补全（监督力最高）

#### P7.1 · 笔记系统增强（**用户明示②**）
- **目标**：让 notes 与 cards 等位，承载「费曼解释」「知识整理」「复习时随手记」
- **功能点**：
  1. 新增 `notes` 表：id/title/content/category/tags/linkedCardIds/linkedDocId/createdAt/updatedAt
  2. 视图 `NotesView.vue`（`/notes`）——增/改/删、按分类与标签筛选
  3. 卡片详情页注入「相关笔记」入口；笔记详情页注入「关联卡片」入口
  4. 双向链接卡片↔笔记（与 6.6 graphEdges 共用边表）
- **复杂度**：中（1 表 + 1 视图 + 双向链接复用 doc-graph 代码）
- **测试**：notes.test.mjs（CRUD/双向链接/筛选/搜索黄金路径）
- **周期**：1 天

#### P7.2 · 资料/卡片/笔记「自动分类」（**用户明示①**）
- **目标**：用户上传资料/建卡/记笔记时，零配置自动归类到已有分类或建议新分类
- **算法（零 LLM 本地实现）**：
  - 提取文本「指纹」：取 TF-IDF top-K 关键词（基于已有 docFiles/cards/notes 的分类字典）
  - 与已有分类打 cosine similarity → 若 max > 0.18 自动归；否则打「未分类」+ 给 top-3 建议
  - 训练数据：用户先手动打几张卡片的分类（seed 数据），跑一次 `trainClassifier()`，后续自动归
- **功能点**：
  - `src/utils/classifier.js`（纯函数）：TF-IDF 训练 / 预测 / 词典维护
  - 服务层 `docs-lib.classifyAll()` 一次性分类所有资料/卡片/笔记
  - 视图 `/categories` —— 类目树 + 文件预览（直接复用 ProgressAI 设计）
- **复杂度**：中
- **测试**：classifier.test.mjs（纯函数 + 黄金路径：建种子→分类→合并误判→修正）
- **周期**：1 天

#### P7.3 · 「导出」通用组件 + 三处落地（**用户明示③**）
- **目标**：解决「笔记、知识图谱、资料」三大块无导出的痛点
- **组件**：
  - `src/components/ExportButton.vue` —— 通用导出按钮（下拉：JSON/Markdown/CSV/Anki apkg）
  - `src/utils/exporters.js` 纯函数：`toJSON / toMarkdown / toCSV / toApkg`
- **落地**：
  1. **笔记导出**：单条 Markdown / 全部 JSON-备份 / CSV 表格
  2. **知识图谱导出**：GraphML / JSON（可被 Gephi/Neo4j 等工具再加工）/ 可视 PNG（用 ECharts 实例的 getDataURL）
  3. **资料清单导出**：`library.export` → Markdown 索引（每条带文件链接与解析文本量）
  4. **卡片导出**：现有 apkg（已支持），增强为可指定过滤条件
- **复杂度**：低-中（纯函数为主 + 三个视图挂载按钮）
- **测试**：exporters.test.mjs
- **周期**：0.5 天

### Phase 8 — 监督力效率（P0，最高杠杆，对应用户 PS 里的强烈诉求）

**研究结论摘要**（Kirchner-Krath 2025 / Lee 2024）：
- *FRIENDLY NUDGES 几乎没用（对拖延）*
- *必须有 SMALL FRICTION / MILD NEGATIVE AFFECT / HOW-TO KNOWLEDGE 才动*
- *不要 over-nudge（推送疲劳 + 快速忽略）*
- *社会问责（social accountability）显著相关*
- *5 大激励原型：结构化进度监控 / 自我提升教练 / 生产力冒险 / 情绪健康教练 / 社交陪伴*

#### P8.1 · 损失可视化（核心监督机制）
- **Dashboard 注入「今日未复习 = X 张，你以为可以摆烂，但考纲还有 Y 天」**
- 实现：复习页上方加 **预警条**——若 due 卡片 > 20 张，红色警示：`⚠ 警告：你今日需复习 N 张，少 1 张 = 你与目标差距 +0.5 张`
- 周末/假期模式：弹出整周欠账汇总
- 错误做法：单纯温和提示 ❌；正确做法：**明确量化损失** ✅

#### P8.2 · 真实紧迫感弹窗（远离 soft-nudge 陷阱）
- 「你昨晚说今天要看，但今日 0 次打开复习。如何不重蹈覆辙？」
- 「本周累计拖欠：N 张。本周复习正确率：M%。你正在拉开与目标的差距。」
- 触发条件：连续 2 天未启动番茄钟、累计 due 卡片 > 50 连续 N 天——触发「自我承诺」弹窗（不给退出按钮，必须读 5 秒或回写一句反思）
- **不可关闭 modal + 5 秒计时**：超过 X 秒不可关闭（逼读）
- 实现：新建 `src/utils/interventions.js`（状态机：提醒/警告/承诺/豁免/逾期）+ Settings 配阈值

#### P8.3 · How-to 知识型推送（最优 nudging 形式）
- 不是「请快去复习」——而是「你最近 5 张卡片的错误都集中在「Cache 一致性」章节。建议：打开资料 📚[标签] 重新读 §3.2，第 N 张卡片 5 分钟前你也错过一次」
- 接入：错题模式 → 自动调 `traceCardSource` → 推送对应原文片段（已有数据能力）
- 频率：每周一 / 周三 / 周日 21:00 推送一次（不要过度推送）

#### P8.4 · 「今日自我承诺」机制（社会问责替代方案）
- 你本地优先 PWA 无云端，不能分享给真人 → 但**「自我记录 + 自我观看」依然有效**
- 启动番茄钟前，必须填一句「今天我要达成 X」（强制输入框，10 字以上）
- 结束时对比昨天承诺 → 周报显示「履约率」
- 实现：plan 表已有，扩展 `dailyCommitment` 字段

#### P8.5 · 「损失对赌」机制（high-friction）
- 自定义「如果今天不复习，明日 due 卡片加倍重排」（用户主动开启）
- 该开关是**反拖延核武器**：开启后系统会真的那样做
- 接入：复习调度/repo.js 的 `review()` 接口

### Phase 9 — 差异化（思维 + 学习路径）

#### P9.1 · 费曼学习法强化（链路笔记第一步）
- 已有 `selfExplanation` 字段（6.6），缺专门 UI
- 新增 `/feynman` 页面：选一张卡 → 输入自我解释 → 系统对比「费曼评分」（能否让大一新生听懂？）→ AI 评分（已有 AI 调用）+ 反复迭代
- 实现：纯 UI + AI 评分（用现有 ai.js Agent）

#### P9.2 · 双向链接笔记（RemNote 模式，本地化版本）
- 让任何文本片段（在卡片/笔记/资料中）变成「`-》 [[笔记名]]`」双向链接
- 与 6.6 知识图谱共用边表
- 实现：在 Markdown 渲染时识别 `-》 [[...]]` 语法 + 在所有视图加反链面板（「谁链向了我」）

#### P9.3 · Benchmark（学习效率基准）
- 已有的 `memoryVisualizer` 提供基础数据
- 升级为「你 P/R 比 / 一致性 / 简历厚度」雷达图，告诉你「你的学习模式是『佛系堆卡型』还是『高效复习型』」
- 接入 dashboard

#### P9.4 · Exam 闭环 / 错题本强化
- 已有 plan / exams 表，缺完整 UI
- 优先级比 P9.1-3 低（用户先要的是监督与基础扩展，不是考试工具）

### Phase 10 · UX 细节（低优先级，可选）

#### P10.1 · 白噪音（番茄钟升级）
- 5 种：雨/森林/咖啡馆/海洋/壁炉
- 实现：可从 freesound.org 选开源音频 + 本地缓存，HTML5 `<audio>` 循环
- 复杂度：低（半天）

#### P10.2 · 多语言（i18n）
- 国际化框架：vue-i18n
- 优先级最低（仅在海外需求时启用）

## 5. 关键风险与权衡

1. **过度监督 = 反感**：P8 全部默认关闭、用户进 Settings 主动开启「监督模式」。**不要强制**。
2. **LTM 写入**：每次复习自动写 reminders 会占 IndexedDB——缓存到 `dailyRollup` 表定期合并。
3. **导出 Markdown 兼容**：必须严格符合 CommonMark，避免用户在 Obsidian/Typora 打不开。
4. **自动分类误判**：第一次启动时无种子数据，必须先用 1-2 张手动分类卡片作为「锚」。体验前期主动引导用户去手动打标。
5. **白噪音版权**：仅用 CC0（公有领域）或自录音频，绝不盗用商业站点资源。

## 6. 不做（明确边界）

- ❌ 多租户/会员/付费墙（背离本地优先 + 数据自主的核心承诺）
- ❌ 协作（需云后端，路线图暂缓）
- ❌ 任意卡片市场/卡组分享（先做好自己的核心体验）
- ❌ 手写识别/手绘笔记（与核心学习闭环弱相关）
- ❌ 完全重做 AI 助手 UI（已有 agent 系统够用）
