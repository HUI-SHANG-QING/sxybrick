## 二、两个新提交深审（均为并行会话自纠的修复，验收通过）

### `ab02803` fix(dbevents) —— P0：跨 tab 广播从未生效（已修）

**大白话**：这个应用有个"一个标签页改了数据，另一个标签页自动刷新"的机制。审计发现它**从上线第一天起就没工作过**——代码用错了 Dexie 的 API（`db.on('creating')` 这种全局级 hook 在 Dexie 里会直接抛错），而外面裹的 `try/catch` 把这个错误**静默吞掉**了。

这是比"修了但没修好"更险恶的失败模式：**装配"看似成功"，运行时一次都不触发**，而且没有任何报错——用户只会觉得"另一个窗口怎么要手动刷新"。修复改用 Table 级 `table.hook`，加 95 行回归测试（含负向对照：把 hook 装回去，测试立刻变红）。

**方法论价值**：这条是"对称性/配对"维度（round54 固化）的又一战果——**try/catch 吞错 + 无实效验证 = 假装配**。凡"失败也要继续"的容错代码，必须同时有"成功路径被证实的测试"。

### `fc86f78` fix(markdown) —— P0 自己引入的回归：黑名单误杀公式（已修）

**大白话**：round123/124 为修 PDF 导出卡顿给 KaTeX 加了黑名单兜底，第一版**凭直觉**把 `svg` 列为禁用标签——但 KaTeX 画**根号、下括号、向量箭头用的是 SVG**！实测误杀 4/16 种正常公式（整段降级成纯文本）。修复：把 svg 从黑名单移除（KaTeX 的 svg 是库生成的固定结构，非用户可控），加 121 行回归（含负向对照）。

**方法论价值**：两个 P0 都是**性能优化引入的回归被自家审计当场抓获**——"修复会引出新问题"的历史规律再次应验，但这次是被审计流程在自己手里拦住了，没有流到用户。

## 三、新向量①：文件导入畸形输入（本维度内零发现）

| 解析器 | 核验要点 | 结论 |
|---|---|---|
| **parseAnkiLines**（TSV/txt，sync.js:534） | 300 行防呆上限（截断如实计数不静默）；坏行（无分隔符→back 为空）**跳过并计数**，不中断整批（旧版会 throw 中断、已入库的不回滚→二次导入重复建卡） | ✅ |
| **stripHtml**（apkg-core.js:20） | `<br>/<div>`→换行、去标签、五类常见实体解码、连续换行折叠——顺序正确 | ✅ |
| **renderAnkiTemplate**（:35） | 字段名过 `escapeRegExp` 再拼正则（防 ReDoS/注入）、`split().join()` 无 `$` 捕获组陷阱、失败字段跳过 | ✅ |
| **parseModels**（:45） | `JSON.parse` try/catch（坏 models JSON 回落空表）、flds 按 `ord` 排序（ord 缺失按 0） | ✅ |
| **noteToCard**（:59） | 模板渲染失败**降级**为"第 1 字段=正面，其余=背面"，不 throw；空正面被上层跳过 | ✅ |

**大白话**：随便拿一个损坏的、恶意的、或者别的软件导出的文件塞进导入功能——最坏结果是"跳过坏行并告诉你跳了几行"，不会崩、不会中断、不会把坏数据混进库。

## 四、新向量②：localStorage 信任边界（本维度内零发现）

全库 **65 处 `JSON.parse`** 清单化，抽样 8 个高危点（localStorage 直读 + LLM 输出）逐点核验：

| 点 | 防线 |
|---|---|
| `ai.js:43` / `embedding.js:18`（读 AI 配置） | try/catch + `\|\| 'null'` 兜底 + 默认值合并（坏配置→全默认，不崩） |
| `useFabDrag.js:108`（悬浮球位置） | try/catch + `Number.isFinite(p.x/p.y)` 坐标校验（坏档→回默认位置） |
| `App.vue:204`（核心导航持久化） | `Array.isArray` 校验 + **path 存活校验**（round29：路由下架后的残留 path 会被剔除，防"导航永久错位"） |
| `plugins/package.js:53`（插件包） | 结构化错误返回（'不是合法 JSON：...'），不 throw 穿透 |
| `agents/base.js:67`（LLM 工具参数） | try/catch + **必须是对象**（拒数组/标量/null，防下游展开畸形） |
| `pipeline-core.js:38`（任务分解） | try/catch + 硬性步数截断（防 LLM 分解出无界步骤烧 token） |
| `batch-image-analysis.js:144`（批量 OCR 回包） | `extractJSON` + try/catch + allowlist 过滤（只收预期 id） |

**大白话**：本地存的每一个 JSON，坏了一律"回默认值/回安全形态"，没有任何一处会让坏数据把应用毒死。这 65 处的纪律一致性是这个库防御深度的又一次实证。
