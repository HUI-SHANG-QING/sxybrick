## 〇、先回答用户最关心的问题：为什么「Agent 看得到、学习助手看不到」

系统里有**两个 AI 入口，取数方式根本不同**，这是差异的根，不是漏修：

| | AI 学习助手（普通问答） | Agent 工作台 |
|---|---|---|
| 入口 | `src/views/AIAssistant.vue:143` → `chatAI`（`src/ai.js:91`） | `src/agent/orchestrator.js` / `agents/base.js runReActAgent` |
| 取数方式 | **没有工具**，靠把数据拼进 1 条 system 消息「喂」给模型 | 持有 **67+ 个工具**，按需自己查（`search_cards`/`get_card_detail`/`list_words`/`read_lib_doc`/`get_image_assets`…） |

| 送图链路 | `llm.js:169 enrichForLlm`（**同一函数**） | `llm.js:169 enrichForLlm`（**同一函数**） |

- **送图能力两边完全一致**（都在 `llm.js:169` 统一富集，一处覆盖全部链路）。round91 修的「摘要裸 `slice` 切坏 `sxy-img://<36位uuid>` → 库里有图却报缺失」在工具压缩出口（`compact.js:36 clipString` 已改用 `clipText`）和 Agent 上下文压缩出口（`base.js:194` 已用 `clipText`）**都已闭环**，本轮复核未发现残留裸截断。
- 普通问答「桌上摆了什么」经过 round92（命中卡全文）、round95（工具补齐）与**当前未提交改动**（全模块明细）已铺得很全。**仍存在的 3 个真实缺口**见 P2-1 / P2-2 / P3-1，以及「资料库 PDF 画面」这一设计取舍。

## 一、P2 · 严重（建议尽快修）

### P2-1　Agent 取「单卡详情」时，长卡片正文被通用压缩砍到每字段约 300 字（承诺「完整内容」名不副实）

**位置**
- 工具：`src/agent/tools/index.js:432 get_card_detail`（description 明确承诺「获取一张卡片的**完整内容**」），execute 原样返回 `front/back`。
- 压缩：`src/agent/agents/base.js:293` 对所有工具结果统一调 `compactToolPayload(res.data)`；
  `src/agent/tools/compact.js:25,30` 默认 `maxChars=6000`、**`maxStringLen=300`**；`shrink()` 对每个字符串字段 `clipString(s,300)`。

**成因**
`compactToolPayload` 的 300 字/字段预算是为 `search_cards` 这种「一次 20 张卡、每张只配摘要」的列表场景调的；但 `get_card_detail` 是「单卡全文」语义，复用同一预算就过紧。触发条件：单卡结果 JSON > 6000 字符（实测 `front+back` 中文合计约 **5500+ 汉字**才越线；**整页思维导图 OCR 文字 + 错题手写详解两面都长的卡**会落在这一档，普通短卡不触发）。

**实证（可复现）**
```
构造 back = 8000 字详解 + 末尾图片引用，front = 2000 字 →
compactToolPayload(data)：原始 10179 字符 → 压缩后 866 字符
  · front/back 各被砍到约 300 字（正文丢失约 96%），并带「本字段共 X 字，已截断」
  · 图片引用 sxy-img://uuid 经 clipText 完整保留（图本身还能送出去，✅ 未被切坏）
对照：4190 字符的卡 < 6000 阈值 → 原样返回，不截断（普通卡不受影响）。
```

**影响**
- Agent 调 `get_card_detail` 看一张长错题/思维导图卡时，**图能看到、但长文字答案只剩开头 300 字**，模型可能基于残缺内容讲解，或误判「背面内容很短」。
- 与普通问答口径不一致：普通问答单卡上限是 `MAX_FULL_CARD_CHARS=1200`（`context.js:135`），Agent 详情反而只有 300——**这正是用户感觉「Agent 也还是看不全」的一个真实来源**。

**修复建议（二选一，均零侵入其他工具）**
- 方案 A（推荐，保真度高）：让 `compactToolPayload` 支持工具级预算——在工具定义上声明可选 `payloadBudget: { maxChars: 12000, maxStringLen: 4000 }`，由 `base.js:293` 透传；`get_card_detail` 作为「单卡全文」工具用更宽预算，列表工具仍用默认值。
- 方案 B（最轻量）：在 `get_card_detail` 的 execute 内对 `front/back/mnemonic/wrongReason` 自行 `clipText(x, 2500)`（两面合计约 5000 字 + 字段名 < 6000，不触发通用 300 字压缩；图片引用同样受保护），超长时标注原长度。
- 任一方案都补一条「长卡 get_card_detail 正文保留度 + 图片引用完整」回归测试。

### P2-2　普通问答 system 消息「无条件全量注入」全模块明细，且整条链路无输入侧字符预算（成本 / 隐私 / 小窗口超限）

**位置**
- `src/views/AIAssistant.vue:135,144`：每次发送都 `Promise.all([buildFullText, buildMemoryText, buildQuestionCardContext(text), buildModuleNodesContext()])`，后三者**无条件**拼进唯一一条 system 消息。
- `src/agent/context.js:186 buildModuleNodesContext()`（**未提交改动**把它从「节点目录」升级为「全模块明细快照」）：备忘全文 + 文档/笔记各 10 篇×500 字 + 计划 6×300 + 每日 7 + 番茄 15 + 单词 15 + 资料库 20 + 图谱边最多 120 条。
- `src/ai.js:91 chatAI` → `trimChatHistory`（`ai.js:71`，**只按轮数留 16 轮，system 整条保留不裁剪**）→ `llm.js chat`：**只夹输出 `max_tokens`，对输入 prompt 没有任何总长度预算**。

**成因 / 对比**
Agent ReAct 路径有总量封顶 `compactConvo`（`base.js:170 CONVO_CHAR_BUDGET=48000`，且只压工具观察/助手原文、绝不动 system/user）；**普通问答没有对应的输入预算**。未提交改动把「全模块明细」做成与问题无关、每轮必发。

**最坏规模估算（按代码上限）**
- 模块明细：文档 5000 + 笔记 5000 + 计划 1800 + 图谱 120 边≈3600 + 单词/番茄/资料/备忘 ≈ 1.8 万+ 字符；
- 命中卡全文：8 张 × 2 面 × 1200 ≈ 1.92 万字符；
- 叠加 RAG 片段、记忆、16 轮历史、OCR 富集追加文字 → system 单条可达 **4 万+ 字符（约 2–3 万 token）**，且**每轮重发**。

**影响**
1. **成本**：用户哪怕只发「你好」，也把全库文档/笔记/单词/计划正文发给第三方模型 API，token 费用随库增大线性上涨（用户付费敏感）。
2. **隐私**：与问题无关的全部学习内容每轮都出站。
3. **小窗口超限**：配 8K/16K 上下文端点（本地/便宜模型）时可能 400 或被服务端静默截断中间历史；该路径没有 Agent 那样的自动收口。
4. 真正相关内容可能被无关明细挤占，反而降低回答质量。

**修复建议**
- 给普通问答的 system 注入加一个**总字符预算 + 按问题意图分级**（Agent 侧已有 `needsFullContext` 分级，`orchestrator.js:106` 可借鉴）：寒暄/闲聊只给统计，问到具体模块才注入对应明细。
- `buildModuleNodesContext` 各段做总预算封顶（超出按相关度/时效裁剪并标注），与 `compactConvo` 口径对齐。
- 该项与第四节「未提交改动」一并决策：方向正确（补齐可见性），建议**加预算后再提交**。

## 三、设计取舍（**非缺陷**，但构成普通问答的可见性边界，需让用户知晓）

- **资料库 PDF/扫描件的画面，普通问答看不到，只能看到文件名清单**（`context.js:239` 已明确注明「需到资料库页打开该文件提问才能看到画面」）。原因：PDF 页渲染成本高，不适合每轮预注入。Agent 侧有 `read_lib_doc` 工具（`tools/index.js:1687`，扫描件自动走 `sxy-doc://` 视觉链路）可按需看图。**结论：要看上传的课件/PDF 原图，走 Agent 或资料库页内提问，这是有意设计而非漏修。**
- 普通问答看不到「未被关键词/语义检索命中」的卡片全文（命中上限 8 张，`FULL_CARD_LIMIT`）；Agent 可任意 `search_cards/get_card_detail`。
