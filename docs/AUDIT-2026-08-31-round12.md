- **根因**：`src/utils/telemetry.js:107` 模块级 `setInterval`（每 10s）在 Node/测试环境保持事件循环非空 → `node --test` 子进程挂起（exitCode 143）。

- **修复**：该定时器仅在浏览器（`typeof window !== 'undefined'`）启动；telemetry 本就是浏览器端采集器，测试/SSR/Worker 不启动。
- **效应**：去掉 `--test-force-exit` 后全量 **668 passed / 0 failed / 0 挂起**（此前为 668/11 假失败）。`package.json` 的 `test` 脚本已移除 `--test-force-exit`，让未来真实失败不再被吞。

- **修复**：

  - 复用：卡片分支直接消费预计算的 `cardDedupe`，避免双重去重计算。
- **回归测试**：`tests/sync-dedup.test.mjs` 新增 3 例——`idRemap` 映射正确性、同 id 路径不产生重定向、导入前关联引用重定向（复刻 `importBackup` 0b 步逻辑，覆盖 reviews/graphEdges/cardGroupLinks）。

## 1. 二次深挖结论

### 1.1 数据对象（DataCloneError 残留风险 · P1 建议，非激活缺陷）
- 现象：`repo.js` 有 60+ 处 `db.X.put({...card})`/`bulkPut`，多数用 `{...card}` 浅展开，未对嵌套响应式代理脱壳；仅 ~8 处用 `plain()`（= `JSON.parse(JSON.stringify(x))`）。
- 实测：关键路径 `createCard`/`review`/`updateCard` 均从**校验值**或 **db 查询结果**（IndexedDB 返回的是 structured-clone 出的纯对象，非 Vue 代理）重建 `card`，嵌套 `fsrs`/`tags` 已是纯对象，**当前不会炸**。
- 风险点：任何未来代码把视图 `ref.value`（含嵌套对象）直接传入 `.put` 即触发 `DataCloneError`（Proxy 不可结构化克隆；`toRaw` 只剥最外层无效）。
- 建议：在 repo 写入口统一 `dbRow()` 脱壳，或为所有 `db.X.put` 加一层包裹（约定级防御）。

### 1.2 数据协同（同步 / 墓碑 / 派生数据）
- `graphEdges` 的 `exportFilter` 排除 `kind='auto'`（派生边重建无墓碑 → 对端永久堆积；id 确定性拼接 → 两端互相覆盖）：口径正确。
- 墓碑 revival：删除经 `tombstone` 跨设备传播；`repo-core` 零复习 `stable=100%` 假满分已修（空数据记 0 + `noData` 标记）。
- 增量同步 `buildIncrementalBackup(lastSyncAt)` 仅导出 `updatedAt > lastSyncAt`：逻辑正确，但**依赖设备时钟一致**，跨设备时钟漂移时可能漏增量（已知权衡，非缺陷；中长期可引入逻辑时钟/版本向量）。

### 1.3 算法
- `graphAuto` 边 id 归一化 + `pairKey` 规范化（round11 已修），`stats` 不再恒 0。
- `forecast` 30 天洪峰同日去重 + 重学上限 8→3（round11 已修）。
- `networth` `isReviewed` 放过 `NaN`（round11 已修）。
- 本轮复核：六维（数值鲁棒性 / 时间语义 / 排序稳定性 / 图算法 / 统计口径 / 输入防御）全实证通过。

### 1.4 业务逻辑
- `pruneTrash` 时钟注入（N-4）；`Stats` 能力雷达渲染恢复（N-2）；`analytics` 画像跨层 i18n（round11）。

## 2. 跨域可拓展 / 可优化（建议，非缺陷）
1. **测试纪律**：telemetry 定时器已按环境隔离。建议立规——**所有模块级副作用**（`setInterval`/`Worker`/`addEventListener`）必须置于 `typeof window !== 'undefined'` 守卫内，避免再次污染测试退出。
2. **构建体积**：`echarts`/`element-plus` 大 chunk（>950KB）可用 `manualChunks` 拆首屏；PWA 预缓存已精简至 119 项（历史 14.8→3.1MB）。
3. **同步健壮性**：增量同步引入单调逻辑时钟，缓解跨设备时钟漂移导致的漏增量（中长期）。
4. **i18n 闸门**：N-3 第三道闸已就位，建议 CI 接入 `check-view-i18n.mjs`（默认 + `--js`），防止跨层中文回潮。
