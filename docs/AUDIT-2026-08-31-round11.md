## 1. P0-1 · graphAuto.js：边 id 不稳定 + stats 恒 0

**缺陷机理（已实证复现）**：
- `add()` 用两套 key：related 走无向 `a|b`，prereq 走有向 `a->b` → 同一对卡能同时留两条边；
- 落库 id 按 `(aId, bId)` 原始先后拼 `auto-a-b` / `auto-b-a`：
  - id 字典序与难度序一致 → 两遍重建同 id，`bulkPut` **静默覆盖**，related 边丢失；
  - 两序相反 → 同对卡两条边并存，各吃掉 `maxEdgesPerCard` 一个名额，图谱重复连线；
- `stats` 用 `rows.filter(e => e.kind === 'prereq')`，而 rows 的 kind 统一是 `'auto'`（派生边标记）→ **恒为 0**，知识图谱页「自动建边统计」永远显示 0 条。

**修复**：边 key 统一 `pairKey(aId, bId)`（排序对），方向存 `aId → bId` 先后；prereq 升级时更新方向 + 标签 + 权重；落库 id 改 `auto-${[aId,bId].sort().join('-')}`（与方向无关，两端设备算出同一 id）；stats 改数内部 `list`（kind 才是 prereq/related）。

**回归测试**（`tests/graphAuto.test.mjs` 追加 3 条）：同序/反序各只落 1 条边、id 一致、库里行数 = 返回数；stats 真实计数；升级后的标签是「前置」。

## 2. P0-2 · forecast.js：遗忘回炉洪峰失效

**缺陷机理（已实证复现）**：rating=0（文档明说是模拟「遗忘回炉洪峰」）时，FSRS 的 again 间隔是亚日级（≈14 分钟），
旧实现 `next.dueAt - reviewAt < MIN_STEP_MS(60s)` 提前 break → `maxIters=200` 只够走约 48 小时 →
**30 天窗口仅前 3 天有数、后 27 天恒 0**，洪峰容量规划完全失真。实测：2000 卡 rating=0，覆盖 3/30 天，耗时 208ms。

**修复**：
- 同日去重：同一张卡同一天只计一次（`counted` key = `${seq}|${dayIdx}`），杜绝「重学 10 次 = 10 张卡」的虚增；
- 同日重学上限 `MAX_SAME_DAY_STEPS 8 → 3`（一次学习同一卡重做 3 次更贴近真实，也更省）；
- 保留小步长退出保护（防止同一卡无限空转）。

**效果**：rating=0 覆盖 **3/30 → 30/30 天**，耗时 **208ms → 109ms**；rating=2 正常推进不受影响。

**回归测试**（`tests/forecast.test.mjs` 追加 2 条 + 修正 2 条旧断言——旧测试把「同日去重」和「后续不再到期」混为一谈）：洪峰必须覆盖大部分窗口、单日计数 ≤ 卡数、总量不得虚增；正常评分次日不退化。

## 3. P0-3 · repo-core.js：零复习假满分

**缺陷机理**：`const total = totalReviews || 1` —— 零复习时 `stable = 1 - 0/1 = 100%`、
`correct = 0/1 = 0%`，新用户看到「稳定度 100% · 正确率 0% · 掌握度 0%」自相矛盾的面板。

**修复**：与 mastery 分支同一口径——无数据记 0，新增 `ability.noData` 标记供 UI 显示「暂无数据」。

**回归测试**（`tests/repo-core.test.mjs` 修正 1 条旧断言——旧测试把错误行为固化成 `stable: 100` 且带注释）。

---

## 4. P1-4 · networth.js：isReviewed 放过 NaN

**缺陷机理**：`typeof f.s === 'number'` 对 `NaN` 也成立 → NaN stability 通过判定后一路污染
`retrievability → 单卡净值 → 全局总净值 → 按来源聚合`，整张报表变一串 NaN 且无任何报错。

**修复**：`Number.isFinite(f.s) && f.s > 0 && f.reps >= 1`。

**回归测试**（`tests/networth.test.mjs` 追加）：`{s: NaN}` 不算已复习；含 NaN 卡的净值聚合不产生 NaN。

---

## 5. P1-5 · analytics.js：画像等级/摘要中文硬编码（跨层 i18n 缺陷）

**缺陷机理**：`getLearningProfile()` 在数据层直接拼中文等级（优秀/良好/中等/待提升）和中文 summary 散文。
切英文界面后「学习画像」卡片（Workspace KPI hint + Stats 画像面板）仍显示中文；问题不在任何 .vue 里，
i18n 硬编码闸门（只扫视图）永远扫不到。与 `repo.bestWorstPartners` 是同一类跨层缺陷。

**修复（三层）**：
1. `analytics.js`：只回 `levelCode`（excellent/good/fair/needsWork）+ 数值 `dimensions`，移除中文 level/summary；
2. `src/i18n/index.js`：新增根字典 `profile.level.*` 四档 + `profile.summary` 插值模板（zh/en 双语）——
   放根字典而非视图字典，因为两个视图都要翻译等级名，各存一份迟早漂移；
3. 消费方：`Workspace.vue` KPI hint 与 `Stats.vue` 画像卡片改用 `t()` 组装。

**回归测试**（新文件 `tests/analytics-profile.test.mjs`，3 条）：数据层不得再返回中文 level/summary；
levelCode 必须落四档枚举；`profile.level.*` 与 `profile.summary` 在 zh/en 下都能解析且插值生效。

## 6. 六维审计完整结论（全部实证）

| 维度 | 方法 | 结论 |
|---|---|---|
| 数值健壮性 | 模糊喂 `null/undefined/[]/[null]/NaN卡` 给 6 模块全部导出纯函数 + 缺陷专项复现 | ✅ 3 处已修（见 §1–4）。残余 `TypeError` 均为**契约外输入快速失败**（调用链 `repo.js` 全部传合法数组），无静默错值 |
| 时间语义 | 扫全部 `86400000` 硬编码 + 日期键生成 | ✅ 全站统一本地零点（`setHours(0,0,0,0)` + `getFullYear/getMonth/getDate`），无 `getUTCDate`/`toISOString()` 混入；天/毫秒无混用；`dayStart+86400000` 在中国无夏令时场景等价次日零点 |
| 排序稳定性 | 扫全部带比较器的 `.sort()`（35 处） | ✅ 均为数值主键 + 稳定次键（`localeCompare`/id 序）或纯数值；无 `a-b` 用在字符串、无相等时返回非 0 的漂移比较器。重点复核：`graphAuto` 权重序（次键 `localeCompare(aId)`）、`local-analyzer` 弱卡优先（主键差值 0.5 阈值）、`intelligence` 科目轮排（`bP-aP`） |
| 图算法 | graphAuto 同对卡双写/覆盖实证 | ✅ 已修（见 §1）：边 key 规范化 + id `[aId,bId].sort()` 与方向无关 |
| 统计口径 | 零复习/空集/样本 1 边界 | ✅ 已修（见 §3）：零复习记 0 + `noData` 标记；`forecast` 同日去重杜绝单日虚增 |
| 输入防御 | 模糊测试 6 模块全部导出函数 | ✅ 快速失败语义符合契约；`selectZombieIds` 4 参签名（误报，调用点传参合法）；`computeStats` 3 参（调用点合法） |
