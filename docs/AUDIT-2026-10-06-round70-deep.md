## 二、新提交 `a5bd956` 深审（round141，验收通过）

**大白话**：AI 工作台有个"双击发送"的口子——loading 锁是在**第一个网络请求发出去之后**才上的，手快的人双击，第二个请求趁锁没上挤进去，变成两条流式回答同时跑（轨迹混杂/偶发丢消息）。修复：锁提前到**发请求之前**。边界也想了：密钥缺失时提前 return，按钮不会锁死。

一句话：**先关门再放人，不是先放人再关门**。1612/1612 全绿。

## 三、新向量①：导出写入面（本维度内零发现）

导出器（exporters.js）的转义链逐点核验：

| 检查点 | 实现 | 结论 |
|---|---|---|
| CSV 公式注入 | `sheetCellGuard`：首字符 `= + - @ Tab 回车` → 前置单引号中和（Excel/WPS 打开不会执行公式） | ✅ round47 已验，仍在位 |
| CSV 转义 | `csvEscape`：RFC 4180 口径——含逗号/引号/换行整段加双引号，内部引号翻倍 | ✅ |
| 行分隔符 | 固定 CRLF（Excel 稳定 + Windows 原生） | ✅ |
| 中文兼容 | `withBOM` 可选 UTF-8 BOM（Excel 中文环境识别需要） | ✅ |
| Markdown 表格 | `escMdPipe` 逐格转义管道符（防用户内容撑破表格结构） | ✅ |

**大白话**：把卡片内容导出成 Excel 能开的文件，不管内容里有什么奇怪字符（逗号、引号、换行、`=`开头的假公式），都不会串行、不会被 Excel 当公式执行。转义链是教科书级的。

## 四、新向量②：userOps 埋点链（本维度内零发现）

埋点数据的完整生命周期核验：

| 环节 | 实现 | 结论 |
|---|---|---|
| **写入** | `telemetry.js:87` 批量 `bulkPut`（攒一批写一次，不逐条打扰数据库） | ✅ |
| **保留期** | `repo.js:870-886`：只留最近 365 天，**超期删除并写墓碑**（单次限量 MAX_PER_RUN 防大清理卡顿） | ✅ |
| **为什么必须写墓碑** | 注释写明：userOps 走 idOnly 合并（"没有这行"≠"删了"）——若只在本机删不写墓碑，其他设备会把老数据灌回来，清理永远清不干净 | ✅ 与全库墓碑纪律同源 |
| **读取** | 全走 `where('t')` 索引游标（:2259/:2290），不做全表扫 | ✅ |

**大白话**：埋点（记录你用了什么功能）这件事以前从没审过——这次查完确认：写入是攒批的（不拖慢操作）、清理是定期的且带着墓碑（别的设备不会把删掉的灌回来）、统计走索引（不卡）。**数据不会无限膨胀，也不会越清越乱。**
