## 三、真机验证**当场抓到**的两个 bug（都已修）

### Bug A：总览页「近 14 天复习趋势」**从来没画出来过**（静默失败）

- **现象**：真机 `/` 页面 `canvas = 0`，图表卡有标题、容器有高度，但里面**什么都没有**。
- **根因**：`Dashboard.vue` 的 `loading` 为 true 时模板是骨架屏，整块内容在 `v-if="loading"` 的
  `v-else` 分支里；而 `renderTrend()` 是在 `finally { loading.value = false }` **之前**调用的
  → 那一刻 `#trendEl` 还不存在 → `if (!trendEl.value) return` **静默返回**，且此后无人再调用它。
- **为什么长期没被发现**：同页其它"图表"其实是纯 CSS（热力格、掌握度条），只有这一张是 ECharts →
  肉眼只看到"图是空的但页面正常"，单测也覆盖不到 DOM 时序。
- **修法**：`await nextTick()` 后再 `renderTrend()`（等 DOM 真正渲染出容器）。
- **✅ 真机复验**：重建产物后同一探针测得 `/` 的 `canvas` **0 → 1**（趋势图出现），全路由冒烟仍 0 异常。

### Bug B：首次进入演示库时，总览页读到**播种前的空库**并永久显示 0

- **现象**（真机 A/B 对照）：首次切到演示模式 → 总览显示「0 今日待复习 / 0% 掌握度 / 资产全 0」；
  **手动重进一次** → 「60 张卡 / 51 今日待复习 / 掌握度 45%」。同一份数据，两次结果不同。
- **根因**：`main.js:61` 是 `useAppModeStore(pinia).init().catch(() => {})` —— **fire-and-forget**
  （模块注释写的是"mount 前 await"，代码没 await）。播种 60 卡 + 96 复习要几秒，而 `app.mount()` 早已执行
  → 视图挂载时库还是空的，**并且共享统计快照把 0 缓存下来**，此后不会自愈。
- **修法**：沿用「切演示模式」已有的做法——**播种完成后 reload 一次**（带 sessionStorage 一次性守卫防死循环）。
- **✅ 真机复验**：修复后**首次**进入演示模式即显示 `60 张卡 / 51 今日待复习 / 掌握度 45%`
  （修复前同一场景是 `0 / 0 / 0%`），且与"再进一次"的结果完全一致、无 reload 死循环。

> 这两个 bug 的共同点：**"页面看着正常、其实是空的"**。单测全绿、构建通过都发现不了，只有真机才能暴露——
> 这正是本轮补真机验证的价值。
