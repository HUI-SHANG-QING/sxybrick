|---|---|---|

→ **失败几乎必然在网络可达性或地址配置，不是同步协议的问题。**

## 按概率排序的排查步骤

### ① 手机里填的中枢地址是电脑的「旧 IP」——最常见（约七成）

电脑重启、换 WiFi、换教室/图书馆网络后，内网 IP 会变（如 `192.168.1.5` → `192.168.0.12`）。
手机同步页的地址存在浏览器本地（`sxy_hub`），**不会自动更新**；而电脑端用 `127.0.0.1` / `localhost`
访问自己，完全不受影响 —— 这正是"电脑能同步、手机不行"的典型成因。

**核对**：
1. 电脑终端执行 `ipconfig`，找 **WLAN / 无线局域网** 的 **IPv4 地址**。
2. 启动 hub 时控制台也会打印全部网卡 IP，并标注哪张是 WiFi 网卡。
3. 手机同步页的中枢地址必须是 `http://<这个IPv4>:18080`。

**最省事的做法**：手机浏览器地址栏直接输入 `http://<电脑IPv4>:18080` 打开应用。
这样页面本身就是 hub 提供的，地址天然同源，同时避开下面的 ②。

### ② 手机用的是 GitHub Pages（HTTPS）打开 —— 混合内容被浏览器拦截

HTTPS 页面调用 `http://192.168.x.x` 属于混合内容，浏览器**直接拦截，请求都发不出去**。
代码里已明确：在 `*.github.io` 上打开时中枢地址默认为空，必须手填，且同步会给出该提示。

**解决**：改用 `http://<电脑IPv4>:18080` 打开；或手机与电脑用 USB 共享网络后使用 RNDIS 地址。

### ③ Windows 防火墙把网络识别成「公用」

本机 localhost 访问不走防火墙，局域网入站会被拦。
**核对**：设置 → 网络和 Internet → 当前网络 → 改为 **专用**；首次启动 hub 的弹窗要点「允许访问」。

### ④ 鉴权失败触发指数退避锁定

同一 IP 连续鉴权失败会被锁定，最长 15 分钟。**限流状态在内存里，重启 hub 即清空。**

## 本轮新增的定位手段（重启 hub 后即可用）

1. **hub 控制台请求日志**：每个请求打印一行
   `[hub] 192.168.1.20 PUT /backup/real → 200 812ms`
   - 手机点同步时**没有任何 `[hub]` 行** → 请求根本没到（防火墙 / 地址错 / 不同网段）
   - **有日志** → 看状态码：401 = 密码不对，400 = 版本不匹配，200 = 成功
   - 只记录 IP/方法/路径/状态码/耗时，不记录 token、challenge、签名与请求体

2. **客户端报错回显目标地址**：同步失败提示末尾会带上
   `｜目标中枢 http://192.168.1.5:18080｜当前页面 https:`
   一眼看出地址填错还是踩了混合内容。

## 建议的执行顺序

1. 重启 hub（清空限流）→ 记下控制台打印的 IPv4
2. 手机浏览器直接打开 `http://<该IPv4>:18080`
3. 同步页点「测试连接」；仍失败则点同步，把**报错全文**（含末尾的地址与协议）发来
4. 同时看 hub 控制台有没有 `[hub]` 日志行
