## 3. 问题清单

### P0-1｜pomo-stats 测试时间依赖，周一必红（真实红测试）

`tests/plugins-examples.test.mjs:127`「pomo_stats：今日/本周/标签聚合」本轮复现失败（`week.sessions` 2 ≠ 3），**单独跑该文件也失败**，与并发无关。

- **根因**：插件 `weekStart` 定义为「本周一 00:00」（`setDate(date − (getDay()+6)%7)`，设计合理）；测试用 `now − 30h` 构造"本周内非今日"样本，隐含假设"30 小时前仍在本周"。今天是**周一**（2026-08-31），本周一 00:00 即今日凌晨，`now−30h` 落在上周 → 断言失败。
- **周期性**：每周一至周二约 06:00 前都会红（30h 窗口越过周一起点）。这是**测试数据缺陷，不是插件逻辑缺陷**。
- **修复建议**：测试数据改用 `weekStart − 1h`（本周内）与 `weekStart − 1.5h`（上周内）相对周一起点构造，摆脱"以运行时刻反推"的脆弱假设；或给测试注入固定时钟。

### P1-1｜demo-mode 全量套件必红：hub 子进程清理触发 libuv 断言（测试基建缺陷）

`tests/demo-mode.test.mjs` 单独跑 **10/10 全绿**；纳入 `npm test` 全量时失败，报错：

```
Assertion failed: !(handle->flags & UV_HANDLE_CLOSING), file src\win\async.c, line 76
```

- **根因**：`before()` spawn 真实 `sync-hub/hub.js` HTTP 子进程，`after()` 仅 `hubProc.kill('SIGTERM')` **不等待退出**；Windows + `--test-force-exit` 下主进程收尾与子进程 handle 关闭竞态，触发 libuv 断言。环境依赖（Windows libuv），属 flaky 基建问题，无功能损失。
- **影响**：全量套件红（本轮 640 测试 638 绿 2 红，其一即此），持续存在会稀释红测试的信号价值——真问题容易被 flaky 淹没。
- **修复建议**：`after()` 中 `await new Promise(r => { hubProc.once('exit', r); hubProc.kill('SIGTERM'); })`（带超时兜底 SIGKILL），让子进程 handle 在主进程退出前干净关闭。

## 4. 多角度交叉分析与建议

**（a）测试体系视角 —— 时间依赖是系统性风险**
20 个测试文件使用 `Date.now()`，本轮暴露 1 个，但 `trash-lifecycle`（9 处）、`integration`（6 处）同样按相对时间构造数据，只是尚未踩中"周一/跨月"边界。建议：
1. 优先修 P0-1（已复现）；
2. 对 trash TTL / 周报 / streak 类按"相对某参考时刻"重构，参考时刻统一注入（如模块接受 `now` 参数，测试传固定值）；
3. CI 或本地跑测前记录 `date`，红测试先判"是否落在时间窗口"再定位。

**（b）i18n 架构视角 —— 质量闸门单向，建议补反向扫描**
`check-view-i18n.mjs` 只验证正向（t() → 字典可解析），本轮 P1-2（漏迁移）、P2-1（回退分叉）、占位符对齐三项均靠人工/临时脚本发现。建议给闸门加 `--strict` 模式：
1. 反向扫描 .vue 中疑似硬编码中文（排除注释、CSS、白名单）→ 防止"迁移完成"声明失实；
2. zh/en 占位符集合对齐校验（本轮 7 字典人工验证，可脚本化进闸门）；
3. 回退字面量 vs 字典值一致性（允许白名单豁免空回退）。

**（c）时间/本地化视角 —— 相对时间未走 locale 通道**
`locale-date.js` 已有 `fmtLocaleDate/Time/DateTime/Number`（绝对时间/数字本地化完成），但 Workspace 的「刚刚 / N 分钟前」相对时间仍是硬编码拼接。建议补 `fmtLocaleRelative(ts)`，底层用 `Intl.RelativeTimeFormat`（零依赖，与现有 i18n 风格一致），Workspace 与后续 UserDashboard 迁移共用。

**（d）数据协同视角 —— 本轮无新风险**
demo-mode 的 real/test 双实例 + scope 隔离 + 409 拒绝机制（上轮验证）本轮未见改动，仍自洽。插件层 `listPomoSessions(2000)` 的 2000 条上限会截断重度用户"本周"统计，属合理的防无界读取，建议仅在插件 description 补一句"统计基于最近 2000 条记录"以免误导。

**（e）扩展功能视角 —— 迁移收尾后的自然下一步**
1. **UserDashboard + Workspace 迁移**（P1-2，约 100 行中文，含图表文案外置）——这是"全站 i18n"真正闭环的最后一块；
2. P2-1 的 24 处回退分叉随迁移批次顺手修复；
3. 上轮遗留的功能型 P2 已全部关闭（P2-20~30），本轮无新增欠账。
