## 🔴 CRITICAL

### C1. `reviewHistory` 对「已删除卡的复习记录」直接崩溃  `[已复核]`
- **位置**：`src/repo.js:957`
  `const cardMap = new Map((ids.length ? await db.cards.bulkGet(ids) : []).map(c => [c.id, c]));`
- **根因**：Dexie `bulkGet` 对「库中已无对应卡片」的 id 返回 `undefined`；紧跟的 `.map(c => [c.id, c])` 在 `undefined.id` 处抛 `Cannot read properties of undefined`。而下一行 `card?.front || '(卡片已删除)'` 明明已预期卡片可能不存在——崩溃发生在兜底生效之前。
- **触发**：任一卡被删（含同步/恢复导致的僵尸卡）后，其 `reviews` 行仍在；打开「已背记录 / 历史」即崩。属 **round33** 把全表 `allCards()` 改成 `bulkGet(ids)` 时引入的回归。
- **修复**：`.filter(Boolean).map(c => [c.id, c])`（拿到结果先滤 undefined）。
- **影响面**：高频路径，用户必触发，且被 try/catch 吞掉后会表现为「记录页空白/报错」。

## 🟠 HIGH

### H1. 所有非卡片 `updatedAt` 表整行 LWW —— 跨设备并发改不同字段丢一端  `[已复核]`
- **位置**：`src/sync-manifest.js:460-486`（`mergeRows` 的 `updatedAt` 分支）
- **根因**：仅 `cards`/`wordCards` 享受 `fieldTs` 字段级合并（round29 P0）。`memos / notes / plans / mindmaps / docs / exams / graphEdges / dailyPlans / dailyTasks / weeklyReports / syllabusMeanings` 等全部走 `if (b > a) m.set(x.id, xr)` 整行取新者。
- **触发**：设备 A 改 memo 标题、设备 B 改 memo 正文（两者 updatedAt 不同），后同步端整行获胜 → 另一端的字段编辑**静默丢失**。与当年卡片 P0 同源，只是未修。
- **修复**：对这些表引入轻量 `fieldTs`（或声明接受该损失并在 UI 提示「此类型跨设备仅整行合并」）。
- **优先级**：用户用笔记/计划/导图且多设备同步时必中。

### H2. 笔记/导图正文 `[[c-card-id]]` 双向链接在导入去重时不重定向  `[已复核]`
- **位置**：`src/sync-dedup.js:103-154`（`remapCardRefs` 仅重写结构化字段）
- **根因**：`remapCardRefs` 覆盖 `CARD_REF_FIELDS / WORD_CARD_REF_FIELDS / ARRAY / JSON / NESTED`，但**不处理自由文本正文**。笔记已支持 `[[c-card-id]]`（`notesView.js:32` 占位符证实）。当两张「异 id 同内容」卡被内容去重（skip→keep）时，指向被跳过卡 id 的 `[[c-oldId]]` 不会被改写 → 悬空链接、点不开。
- **触发**：同一卡在两台设备各自新建（不同 uid）→ 任一端导入对方备份触发去重。
- **修复**：`remapCardRefs` 内对 `notes/memos/mindmaps` 的 `content` 做 `[[c-${old}]]`→`[[c-${kept}]]` 文本替换（先占位符扫描再替换，避免误伤形如该串的其它文本）。

### H3. 单词卡 EXT 字段把 Vue 响应式 Proxy 直接写进 IndexedDB → DataCloneError  `[已复核]`
- **位置**：`src/word-repo.js:162-168`（`pickExt` 直接 `out[k]=payload[k]`）、`:229-231`（`updateWordCard` 直接 `next[k]=patch[k]`）、`src/views/WordBook.vue` 的 `parseExt()`/`autoGenerateSilent` 从 `form.value` 读响应式数组
- **根因**：`createWordCard`/`updateWordCard` 入口未对 `payload` 做 `plain()`。AI 自动填充（`form.value.defs = d.defs`）或用户编辑释义/例句后保存时，`form.value.defs` 等是响应式数组 → `db.wordCards.put(card)` 抛 `DataCloneError`，被 `save()` 的 catch 当「保存失败」吞掉。空字段时 `blankForm()` 未初始化这些字段（undefined→`[]` 新数组）不触发，故呈**间歇性**。
- **修复**：`createWordCard`/`updateWordCard` 入口对 `payload` 做 `plain()`（同文件已有 `plain` 仅用于 trash）——防御式去 Proxy，根绝一类 DataCloneError。

### H4. `dashboardSnapshot` 缓存跨「真实库 ↔ 演示库」泄漏  `[已复核]`
- **位置**：`src/repo.js:997-1019`
- **根因**：缓存键仅 `${cc}|${rc}|${cLast.updatedAt}|${rLast.reviewedAt}`，缓存是模块全局 `let _dashSnap`。`setDbInstance` 切换 IndexedDB 实例**不会重置缓存**。若真实库与演示库碰巧产生相同 count/时间戳键（如都空 → `0|0|0|0`，或都种子到相等数量），切换模式后 `getStats/weakCards/getReviewSuggestion` 返回**另一模式**的 cards+reviews。
- **触发**：进演示模式再退回真实模式、或两模式先后进入 Dashboard 撞键。
- **修复**：缓存键纳入当前 DB 身份（库名/标识），`setDbInstance` 时清空 `_dashSnap`/`_failCountCache`。

### 数值 / 算法
- **M11. FSRS `trainWeights.lossOf` 首测用伪造 R≈1 计分** `[审计报]` `src/fsrs.js:269-294`。`init` 分支 `reps=1; last=revs[0].reviewedAt`，`j=0` 时 `elapsed=0 → R=retrievability(s,0)=1`，对首测（本无先验状态）计入 loss。有限差分梯度不受影响（优化仍收敛）但 `n` 每卡 +1、报告 loss 失真。→ 非 init 分支设 `reps=0` 且 `last===reviewedAt` 时跳过 loss（镜像 `backfillCardCalibration`）。
- **M12. `stabilityAfterRecall` 不 clamp `D`** `[审计报]` `src/fsrs.js:118,126`。所有内部调用方都经 `nextDifficulty` clamp，但函数本体用原始 `D`；若任何路径传入未 clamp 的 `card.fsrs.d`（或直测），`D>11` 使 `factor` 为负 → `nextS` 可能 ≤0.1 被钳 → 静默把间隔锁死。潜在。→ `const dEff = clamp(D,1,10)` 用 `(11-dEff)`。
- **M13. `easyBonus`(w16) 可拟合到 <1** `[审计报]` `src/fsrs.js:122,265`。结构护栏只防 `w15(hard)>1`；梯度界 `[0.01,100]` 可让 `w16<1` 使 grade-4「简单」弱于「良好」。现生产不发射 grade 4（`toFsrsGrade` 上限 3）故当前死代码，但启用即反转。→ `easyBonus = Math.max(1, w16)`。
- **M14. Hub MIME 缺 `.wasm`** `[审计报]` `src/sync-hub/hub.js:61-81`。`dist/` 实有 `.wasm`（PDF.js/字体）。若用 `instantiateStreaming` 加载需 `application/wasm`，octet-stream 直接抛错 → 局域网离线功能静默失效。→ 加 `'.wasm':'application/wasm'`。
