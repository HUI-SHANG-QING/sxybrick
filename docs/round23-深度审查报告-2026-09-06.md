## 一、问题清单（按严重度；★=主审已亲自读码复核）

### P1（会造成数据错误/重复/丢失）

**P1-1 ★ WordBook `save()` 无防重入锁，双击可创建重复词卡**
- 位置：`src/views/WordBook.vue:342-371`（save）、`:820-826`（保存按钮无 `:disabled`）
- 问题：新建路径连点两次保存 → 两次 `createWordCard`（各生成新 uid，`wordCards.word` 无唯一索引）→ 重复词卡；编辑路径虽幂等但会重复弹 toast。
- 根因：只有 `genRunning` 禁用了「AI 生成」按钮，`save()` 无 `saving` ref，且 create 无唯一约束兜底。
- 建议：`save()` 入口加 `saving` ref 防重入 + 保存按钮 `:disabled="saving"`；可选：`listWordCards` 层对同 kind+同 word 去重提示。

### P2（边界缺陷 / 潜在错 / 挂死根因）

**P2-1 ★ 默认 SM-2 调度下卡片永不写 FSRS 状态 → 知识净值/保持率失真**
- 位置：`src/repo.js:57`（默认 `scheduler='sm2'`）、`src/srs.js:229`（仅 fsrs 分支返回 `fsrs`）、`src/repo.js:~528`（`fsrsNext = next.fsrs ?? (card.fsrs ? {…last} : undefined)`）、`src/algorithms/networth.js:22-28`（`isReviewed` 要求 `fsrs.s` 有限且 reps≥1）
- 问题：**默认调度是 SM-2**。SM-2 出生的卡（从未切过 FSRS）`card.fsrs` 恒 undefined → `isReviewed()` 恒 false → Health/仪表盘「知识净值 totalValue=0、折旧=0、保持率分母缺失」，把"已背过"当"没学"。
- 根因：净值口径绑定 FSRS 状态，但 SM-2 路径不产出该状态；无"跨调度器已复习"的等价信号。
- 建议：`isReviewed` 增加 SM-2 等价判定（`reviewedAt>0 && (level>0 || intervalDays>0)`）；净值折旧在 SM-2 下用 SM-2 的 E-Factor 等效 R 或至少按"已复习→按上次复习天数线性/表格折旧"，避免默认配置下整表为 0；或引导默认 FSRS。**此为数据层口径缺口，改动需回归 networth/analytics 测试。**

**P2-2 ★ 字段级/行级 LWW 合并在跨设备时钟偏差下无保护 → 近时并发编辑可丢**
- 位置：`src/sync-manifest.js:273-289`（`updatedAt` 策略裸 `b >= a` 取新）、对照 `src/sync-status.js` 的 `SYNC_STATUS_SKEW_MS=5min`（只用于展示判定，未参与合并）
- 问题：两设备近时（<5min 内）改同一卡，时钟偏慢一方的"较新"编辑因时间戳更小而**被整体覆盖**；5min 容忍只修了状态面板的假 pending，没修合并本身。
- 根因：本地优先单文件合并天然 LWW；skew 常量口径未下沉到 `mergeRows`。
- 建议（按成本选一）：① 合并侧同样加 skew 容忍（`b >= a - SKEW`，代价：可能短暂回退自己刚改的 <5min 变更，靠下次同步自愈）；② 内容表由整行替换升级为**字段级**合并（至少对 modeQuestions/note/tags 这类独立编辑字段）；③ 文档明示 LWW 限制并展示"最后同步于对端 xx"提示。推荐 ② 为长期方向。

**P2-3 ★ `word-llm.js` 直连 provider 的 `fetch` 无超时 → 批量出题/补释义可永久挂死**
- 位置：`src/services/word-llm.js:165`（`callChatCompletion`）、`:282`（`testLlmConnection`）
- 问题：agent 通道有 60s 超时，但用户 Key 直连路径无 `AbortSignal`；provider 不响应时 `batchGenerateMeanings`/`batchGenerateModeQuestions` 逐卡挂死、进度条定格、按钮永远转圈。
- 根因：与 Sync hub 同一类问题（`sync.js:498` 已修），此处遗漏。
- 建议：对齐 `AbortSignal.timeout(30000)`，超时报可读错误；`testLlmConnection` 用 10s。

**P2-4 WordAIModes 批量「停止」只置标志位，不能中断在途请求**
- 位置：`src/views/WordAIModes.vue:93/103/312`；根因即 P2-3（无 signal 可传）。
- 建议：把可取消 `signal` 透传进 `callLlmJson`（agent 分支已可传，补 key 分支），stop 时 `abort()`。

**P2-5（设计裁定项）AI `modeQuestions` 落库+同步但复习流零消费 → 死存储与口径漂移风险**
- 位置：`sync-manifest.js:45`（EXT_FIELDS 并集同步）vs `src/views/WordReview.vue`（全文件零引用 modeQuestions）；仅 `WordAIModes.vue:264` 预览。
- 问题：AI 生成的 13 模式题每张卡存一份并跨设备同步，但复习判分是**确定性运行时生成**，两者同构性无运行时校验 → 存储/同步/合并空转，未来若一端改了 answerSide 口径即漂移。
- 建议（择一）：A. 复习流真正消费 modeQuestions（如 flashcard/englishEnglish/quiz 优先用 AI 题面，无则回退本地生成）——闭环 AI 价值；B. 明确其为"离线预览/练习题库"并评估是否保留在同步字段，或仅存本地不同步。倾向 A。

### P3（健壮性/潜伏/知情项；★=已复核）

- **P3-1 ★ sync-status 大表(>5000 行)「保守待同步」兜底失效**：`sync-status.js:153-155` `maxTs=Math.max(maxTs,1)`，而 pending 判定 `maxTs > lastSyncAt + SYNC_STATUS_SKEW_MS(5min)` → 值 1 永不可能触发（加 SKEW 后更死）。userOps/embeddings 超 5000 行后新变更永不显示待同步。建议：改按 liveness 时间戳索引 `orderBy('updatedAt').last()` 精确取 max；无索引表保留"采样"并注释该表不走精确判定。
- **P3-2 ★ F10「已清空水位」过滤在 cards 表被去重结果覆盖**：`sync.js:647-659` `clearedBefore` 过滤先作用于原始 incoming，随后 `incoming = cardDedupe.kept` 整段替换 → 滤除结果丢弃。cards 暂无清空入口，属潜伏缺陷；建议 dedupe 后再跑一次 `filterClearedRows`。
- **P3-3 ★ images 表无任何时间戳（`db.js:27 images:'id'`），墓碑按 `deletedAt` 裁决** → 共享同一图的另一张活动卡存在时，对端删卡级联墓碑可能误删本端仍引用的图片（liveness=0 恒 ≤ deletedAt）。建议删除前做引用计数或由 cascade 的 used 集决定是否写图墓碑。
- **P3-4 ★ meta 仅同步 `goal` 单键**（`sync.js:766-772` 注释自承）：FSRS 权重/调度器选择等换机即失。已知缺口，建议评估 meta 白名单同步（排除 deviceId）。
- **P3-5（未逐一复核）hub 始终合并并回传 privacyRecords，向未 opt-in 客户端回传**：局域网多端共享 hub 时隐私行在网络层传输。建议客户端在 `effTables` 不含隐私表时主动剔除返回体中的 privacyRecords。
- **P3-6（未逐一复核）`uid()` 回退（非 randomUUID 时 Date+random）非全局唯一 + `importBackup` 未校验 `BACKUP_VERSION`**：高版本包被低版本代码导入会静默丢字段。建议导入前比对 version 告警。
- **P3-7（未逐一复核）WordBook 多标签页列表陈旧**：无 liveQuery/BroadcastChannel，tabA 编辑后 tabB 刷新前看不到。建议轻量 broadcast 失效。

1. **全表 `toArray()` 扫**：`getModuleStatus`/多表统计对 >5000 行表做 cap 采样（见 P3-1）；`listWordCards` 每次全表读后内存过滤（`word-repo.js:354-378`），词表上万时首屏/筛选有可感延迟 → 建议按需分页 + kind/词首索引，至少把 `updatedAt` 索引建上（当前排序字段无索引）。
