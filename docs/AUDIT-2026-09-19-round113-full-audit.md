## 二、关键逻辑核查

### 1. 预览层放大/全屏（round120 → round121）
- **演进**：`min(720px, 92vw)` → `min(1180px, 97vw)+94vh` → 全屏 `100%×100%`（去掉圆角/描边/外阴影/遮罩留白）。
- **设计取舍合理**：超宽屏上正文行长过长反而难读 → 用「内容列随屏宽留白（padding: 18px clamp(16px,7vw,140px) 32px）」解决，而不是压窄窗口。
- **真机验证充分**：宽屏 1280 → wrap 1232×804 适配；窄屏 420 → 489×704 < viewport 504×704 无横向滚动；翻转正常（真实鼠标点击验证 rotateY 矩阵）；关闭正常；零未捕获异常。

### 2. 清晰度"不清晰"的定案（本轮的硬核部分）
- **不是分辨率问题**：用 sharp 做 Laplacian 卷积求灰度标准差（数值越大越锐），DPR=1.25 实测：
  - 弹窗内 H1（3D 原样）35.27 > 页面标题 28.76 > 筛选标签 8.26 → **弹窗内的字比页面其他区域都更锐**；
  - FlipCard 的 3D 上下文只带来约 3.8% 损失，人眼不可辨 → **未改动 3D 结构**（避免为微小收益引入翻转视觉回归）；
  - 正反面逐字相同卡实测：正面 38.30 / 反面 37.69（差 1.6%，噪声范围）→ 不存在正面特有的渲染降级。
- **结论**："不清晰"的真实来源是**内容偏小**（字号小 + 行长短），本轮从可读性下手（正文 15px / 行高 1.75）。
- **作用域安全**：Cards.vue 为 `<style scoped>`，只影响预览层，不影响卡片列表/背诵页/AI 回复的 Markdown（有测试钉住此边界）。

### 3. 死样式清理（a9612fe）
- 发现 `border-radius/border/box-shadow` 三行旧声明被同优先级**后声明覆盖**，永不生效 → 删除，并在测试里钉住"每个属性只能声明一次"，防同类静默问题复发。审计视角看是对的：视觉上无差别（全屏后圆角在屏幕外），但消灭了失效声明。

### 4. `100vw`→`100%`（29a7021）
- **真隐患**：`100vw` 包含竖直滚动条宽度，页面出现纵向滚动时预览层会比可用宽度宽十几像素 → 凭空多出横向滚动条。父级 `.preview-mask` 是 fixed+inset:0，用 `100%` 即视口可用宽高。修法正确。
- 另诊断确认：截图里那条横向滚动条实际来自顶部导航菜单窄窗口溢出，与预览层无关（但 100vw 写法本身有隐患，一并修正）。
