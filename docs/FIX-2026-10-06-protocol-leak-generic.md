## 一、举一反三：探针实测结果

探针 `tests/agent-protocol-probe.test.mjs` 覆盖 10 种形态，**修前**的结果：

| 形态 | 修前 | 修后 |
|---|---|---|
| DSML `＜｜｜DSML｜｜＞` | ✅ round133 已修 | `final=null` |
| **XML 风格 `<function_calls><invoke …>`** | ❌ **泄漏** | `final=null` |
| **OpenAI 风格 `<tool_call>{…}`** | ❌ **泄漏** | `final=null` |
| **Qwen 风格 `<\|tool_calls_section_begin\|>`** | ❌ **泄漏** | `final=null` |
| **ReAct 老格式 `Action:` / `Action Input:`** | ❌ **泄漏** | `final=null` |
| **`<thinking>…` 思考过程** | ❌ **内部思考被当正文显示** | **只保留正文** |
| **DeepSeek `<think>…`** | ❌ 同上 | **只保留正文** |
| 4 条回归基线（正常回答 / 数学公式 `a < b` / 无标签自由文本 / 截断 `<final>`） | ✅ | ✅ **一字未变** |

**两个关键观察**：
1. OpenAI 风格那个 `<` 后面藏着**零宽字符**（U+200B）——这是模型输出的真实脏数据，
   直接拿原串做正则会漏；
2. 思考标签**不该整段丢弃**——用户真正要的是思考之后的正文，剥掉思考保留正文更合理。

## 二、修复（通用防护，不再是打补丁）

### 2.1 规范化后再判
`norm()` 先剥掉 `U+200B/200C/200D/FEFF`（**不动任何可见内容**），再交给协议检测 ——
否则模型插一个零宽字符就能绕过所有正则。

### 2.2 协议检测（`looksLikeToolCall`）
任一已知厂商协议形态命中即判定为「工具调用」：
DSML / `function_calls` / `tool_call(s)` / Qwen 的 `<|tool_call|>` / ReAct 的 `Action:` 行。
**宁可少答也不泄漏**（宁枉勿纵）。

### 2.3 思考剥离（`stripThinking`）
`<think>` / `<thinking>` 的**成对、未闭合、只有结束标签**三种形态都处理
（流式抢救时"只有开始标签"极常见），**保留正文**；剥完为空才返回 null。

## 四、门禁两次抓出我自己的错误（本轮最有价值的部分）

用户反复说"每轮修复都会引出问题"。这一轮**确实又引入了两个**，但都被门禁当场抓住：

1. **`t` 遮蔽**：`looksLikeToolCall` 里写了 `const t = norm(raw)`，
   而本文件 import 了 i18n 的 `t()` —— 同块内任何 `t('key')` 都会抛 `t is not a function`。
   被 `tests/vue-template-guard.test.mjs` 拦下（这是项目 §8 的既有铁律，我记得却仍踩了）。
2. **零宽字符进注释**：为展示真实形态，我把 U+200B 真写进了注释 →
   被 eslint 的 `no-irregular-whitespace` 拦下。

**结论**：这两类错误**静态检查就能拦**，代价是零。
**"修复引入问题"不可怕，可怕的是没有门禁。**

## 五、广度审计（非 AI 链路）：**未发现新问题**

| 检查项 | 结论 |
|---|---|
| **3 处 `v-html` 出口** | ✅ 全部安全。`MarkdownRenderer` 走 DOMPurify；`Cards.hlFront` 的 `highlight()` 做了 `& < > " '` **完整五字符转义**，且模板用 `v-if="filters.q"` 保证只有走高亮分支才用 `v-html`；`LibraryFiles` 的表格/Word 预览已净化。**注释声称与实现一致**（我逐个核对了，没信注释） |
| 关键 `JSON.parse` 兜底 | ✅ `pipeline-core` 的 LLM 输出解析有 `try/catch → null`；`ai.js` / `embedding.js` 的 localStorage 解析在 `try` 内 |
| 错误消息含服务端响应 | ✅ 有意设计（`explainLlmFailure` 要求"失败原因必须如实"），服务端不回显 API Key，无泄漏 |
| `toast(e.message)` 15+ 处 | ✅ 开发工具的常规做法，保留技术细节有助自助排障 |

**唯一记档不改**：`search/highlight` 用搜索词构造 `new RegExp`，
超长搜索词会生成巨大的正则（性能/ReDoS 边缘情况）。
搜索框长度受限，暂不构成风险，**未改**。

## 六、诚实边界

1. **探针覆盖的是我预想到的 10 种形态**，无法穷举模型的所有怪输出；
   但防护设计是**通用规则匹配**（不是逐个格式打补丁），覆盖面显著优于专项修复。
2. **未在真实模型上端到端验证**（沙箱无凭据），验证基于用户提供的真实文本样本 + 探针。
3. 广度审计的"未发现新问题"仅覆盖上表四项，**不代表全仓穷尽**。
4. 本轮改动的 `base.js` 是 Agent 主链路，**风险面较大**——因此负向对照与 4 条回归基线
   （尤其"无标签自由文本整段返回"这条被多个调用方依赖的既有行为）都单独锁住了。
