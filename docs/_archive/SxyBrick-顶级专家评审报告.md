## 一、执行摘要

**总体定位**：SxyBrick 是一个以"本地优先（Local-First）+ 间隔重复（SM-2 增强）+ 轻量 AI Agent"为核心、面向考研复习场景的渐进式 Web 应用（PWA）。它不是又一个 Anki 克隆，而是试图把**记忆科学、学习分析、Agent 编排、知识图谱、数据可移植性**揉进一个零后端、零成本、可离线运行的单页应用。在工程野心与完成度上，远超一般课程设计/毕业设计水准，已具备"准产品级"雏形。

**最大亮点（三位一体）**：
1. **架构纪律性**：`sync-manifest.js` 作为"同步唯一事实来源"，被浏览器端 `sync.js` 与 Node 端 `hub.js` 共用同一套纯合并函数——这是教科书级的"单一事实来源"实践，从根上消灭了"导出/导入/局域网中枢三处合并逻辑不一致"这类经典分布式同步 bug。
2. **同步正确性设计**：卡片"内容字段按 `updatedAt`、SRS 字段按 `reviewedAt`"的**双时间戳字段级合并** + 带 `kind` 的墓碑传播，解决了一个真实且隐蔽的数据丢失问题（复习动作不应覆盖文字编辑，反之亦然）。并配有回归测试佐证。
3. **认知科学依据**：SRS 在经典 SM-2 之上引入"短期巩固窗口（当日 6h + 隔日）"，明确引用 Roediger & Karpicke (2006) 的测试效应，方向正确。

**最值得警惕的风险（按严重度）**：
- **P0 同步正确性**：`wrongReason` 与 `consolidation` 两个字段被错误归类（详见 §五 R1、R2），导致"复习时写入的错因"和"短期巩固调度状态"在跨设备同步时可能静默丢失。这是本评审发现的**最高价值、最具体**的缺陷。
- **P0 数据资产脆弱性**：全量复习语料仅存于单设备 IndexedDB，**没有自动、加密、离设备的备份通道**。浏览器缓存清理/换机/重装 = 数据归零。与"数据资产化"主张直接矛盾。
- **P1 算法缺乏校准**：DIFF_FACTOR、wrongPenalty、GRADUATED_STEPS、图谱推荐阈值均为**启发式硬编码**，无基于用户真实数据的 A/B 或纵向验证。
- **P1 测试覆盖过窄**：CI 门禁 `npm test` 仅覆盖 `srs.js` 与 `sync-manifest.js` 两个纯函数模块；24 个视图、`intelligence.js`、`analytics.js`、`orchestrator.js` 等最易出错、最复杂的模块**零自动化测试**。
- **P1 可扩展性**：`analytics.js`/`intelligence.js` 多处对全表 `toArray()` 做主线程 O(n²) 计算，千卡级以上存在卡顿隐患。

## 二、分专家视角审视

### 2.1 软件架构与工程质量（Architecture & Engineering）

**评级：A-（优秀，局部有技术债）**

**架构分层（清晰、低耦合）**：
```
[ 视图层 Views (24 routes, 懒加载) ]
        │
[ 业务/智能层 intelligence.js / agent/* (编排·RAG·主动智能体) ]
        │
[ 数据访问层 repo.js + analytics.js（统一只读分析，跨模块协同）]
        │
[ 持久层 db.js (Dexie/IndexedDB, v12 增量迁移) ]
        │
[ 同步层 sync-manifest.js（唯一事实来源）+ sync.js / hub.js ]
        │
[ 算法层 srs.js（纯函数，可测）]
```

**值得肯定的工程实践**：
- **单一事实来源**：`SYNC_TABLES`/`mergeRows`/`mergeTombstones`/`applyTombstones` 为无浏览器依赖的纯函数，前后端共用，杜绝逻辑分叉（R11）。
- **响应式代理剥离**：`plain()`（`JSON.parse(JSON.stringify(x))`）在写 IndexedDB 前剥离 Vue 响应式代理——这是踩过"结构化克隆失败"坑后沉淀的硬经验，说明团队有"失败→复盘→固化"的成熟回路（R12）。
- **构建优化**：`vite.config.js` 用 `manualChunks` 把 three/echarts/katex/element-plus 等重依赖切独立 chunk + 路由懒加载，首屏体积可控；`chunkSizeWarningLimit: 950` 体现体积纪律。
- **健壮性**：全局 `errorHandler` + `unhandledrejection` + 本地错误日志表（`errors`）+ 离线 AI 兜底（`offlineAI.js`），构成"看不见的崩溃"防护网。
- **CI 质量门禁**：`deploy.yml` 先 `npm test` 再 `npm run build`，测试失败不发布——这是专业级发布纪律。
- **设计模式**：Agent 框架的开闭原则（`registerTool`/`registerAgent`）、意图路由零 token 开销（关键词启发式）、RAG 远程失败自动降级本地 bigram——都是务实且优雅的取舍。

**隐忧**：
- **技术债密度**：Dexie 已迭代到 v12，24 张表/实体；虽每次迁移向后兼容，但 schema 表面积大，任一新字段忘记登记进 `SYNC_TABLES` 就会静默不同步（事实上 R1/R2 正是此类遗漏）。
- **Bus Factor = 1**：高度定制、单作者、无 LICENSE/CHANGELOG/贡献指南（git 历史即文档）。`intelligence.js` 单文件约 800 行、`analytics.js` 约 540 行，集中了最复杂的算法，维护风险高。
- **术语一致性**：提交记录出现"GitHub Pages 同步失败"修复——需厘清"GitHub Pages 同步"实为"静态托管应用"，真正同步是**文件导出导入**或**局域网中枢**。对外表述若混淆，会误导用户预期。

### 2.2 算法与学习科学（Algorithm & Learning Science）

**评级：B+（方向科学，参数未校准，统计口径有瑕疵）**

**SRS（srs.js）评估**：
- ✅ 在经典 SM-2 之上系统化扩展：难度系数 `DIFF_FACTOR=[1.15,1.0,0.8]`、错因惩罚 `wrongPenalty`、蒙对检测（`guessed`）、强度系数 `intensity`、自适应节奏（近 10 次错误率微调）、短期巩固状态机。
- ✅ 短期巩固窗口（6h + 隔日）符合"测试效应"与"睡眠对记忆巩固"的实证方向；`GRADUATED_STEPS=[1,3,7,15]` 是经典梯度变体，合理。
- ⚠️ **参数缺乏实证校准**：`DIFF_FACTOR`/`wrongPenalty`/`GRADUATED_STEPS` 的具体数值是作者经验值，没有"在你的数据上，这些间隔比 vanilla SM-2 提升了多少 retention"的纵向研究。作为研究型工具，建议内置 A/B 或至少"实际留存率 vs 预测"的回测面板。
- ⚠️ **掌握度口径失真**：`getStats()` 的科目掌握度仅用"近 90 天自评均分/2"（repo.js:367-379）。一张早已稳定掌握、但 90 天内没复习的旧卡会被算成 0% 掌握——与用户直觉"我早就熟了"冲突，也会污染 Dashboard 的"数字孪生"叙事。
- ✅ 有 `srs.test.mjs` 覆盖评级路径/难度/错因/蒙对/上限/自适应等 11 个用例，质量扎实。

**推荐算法（intelligence.js）评估**：
- ✅ `recommendGraphEdges` 做了多信号融合（标签重叠 + 余弦 + Jaccard + 变式同源 + 共现），并对跨科目抽样以抑制 O(n²) 爆炸——工程思考成熟。
- ⚠️ **同科目内仍是全两两比较**（intelligence.js:191-198），未设上限；单科目数千卡时仍可能卡顿。阈值（cosine≥0.15/0.2、jac≥0.15/0.18）为拍定经验值，可能产生噪声边（如两卡共享同一数学符号）。
- ⚠️ `recommendTodaySequence` 的精力曲线（早/午/晚）按**设备本地小时**粗分，未考虑用户个性化作息；属合理简化但非个性。

**RAG（embedding.js / retrieval.js）**：
- ✅ 远程 embedding 失败自动降级本地 bigram+TF 哈希（256 维，L2 归一化），保证离线可用、零依赖。
- ⚠️ 本地降级本质是"关键词重叠"，无语义；且 **embeddings 表未纳入 `SYNC_TABLES`**，换设备后 RAG 索引为空，检索静默失效，需手动 `rebuildIndex`（见 R3）。

### 2.3 产品经理视角（Product Management）

**评级：B（功能广度惊人，核心闭环聚焦度待强化）**

**价值主张**："离线、免费、数据私有、可移植、带轻 AI 的考研记忆系统"——清晰、差异化、契合目标用户（跨考、注重隐私与成本）痛点。

**优势**：
- 零成本部署（GitHub Pages）+ 零后端 + 数据本地，构成强信任壁垒。
- 功能矩阵极其完整：复习、错题、费曼、计划、知识图谱、思维导图、番茄、模考、周报、成就、书房、健康、AI 助手、Agent 工作台、同步——几乎覆盖"学—练—测—评—管"全链路。
- "学习数字孪生 Dashboard"作为首页，把分散数据收敛成可决策的概览，产品思路高级。

**产品风险**：
- **功能蔓延（Feature Bloat）**：24 个一级页面。对"强化期考研生"而言，**注意力是稀缺资源**。核心闭环（加卡→按曲线复习→错题补救）可能被 Agent/主题/图谱/书房稀释。需做"主路径瘦身 + 高级功能折叠"。
- **激活 vs 分析失衡**：Dashboard 强调"数字孪生/资产叙事"，但**"立刻开始复习"这一最高频动作是否足够一键可达**需审视（有提交记录修复"Dashboard 卡片块误跳首页"，说明首页交互曾出问题）。
- **留存机制单薄**：打卡由 reviews 推导 + 成就系统起步，但缺乏"间隔提醒/学习契约/同伴"等强留存杠杆；长周期（考研近半年）坚持靠自律，产品可做的"助推"有限。
- **可发现性与上手成本**：24 视图 + Agent + 多主题 + 三套同步方式，对新手门槛高。虽有引导，但"借鉴 Progress AI"的模块（导图/周报/成就）是否带来净留存增益，需数据验证。
- **竞争定位**：相对 Anki（生态/插件/跨端同步成熟）、相对商业 App（如墨墨/不背），SxyBrick 的差异化在"本地私有 + 轻 AI + 零成本 + 可移植"，但**自动跨端云同步的缺失**是其 vs 商业 App 的最大体验短板。

### 2.4 数据资产化（Data Assetization）

**评级：B-（理念领先，落地有硬伤）**

**资产化的正确实践（亮点）**：
- **本地优先即资产所有权**：用户数据永不离境，无供应商锁定（vendor lock-in），真正"数据是你自己的"。
- **可移植性强**：全量 JSON 备份、CSV/TSV、Anki 纯文本互通、按科目卡组分享（带 `deckMeta` 作者署名，E2）——多通道导出是资产流转的典范。
- **资产体检（E1）**：`getAssetHealth()` 做重复卡/僵尸卡/孤儿图片/无标签卡诊断，体现"数据要保值"的资产治理意识。
- **资产叙事（E3）**：书房/Library/个人主题/模考走势，把冷数据讲成"我的学习资产故事"。

**资产化的硬伤（必须正视）**：
- 🔴 **无自动离设备备份（R4）**：所有数据仅存浏览器 IndexedDB。一次"清除站点数据"/换机/系统重装即**永久丢失**。对把全部复习语料押在上面的考研生，这是**单点灾难**。当前"同步"只是手动文件或局域网中枢，均依赖用户主动操作，且中枢文件 `hub-data.json` 已 21MB（图片 base64 膨胀），不是可持续备份方案。
- 🔴 **资产不完整（R3）**：导出包不含 `embeddings`/`notifications`/`errors` 表；RAG 索引与"主动智能体"通知不随资产流转，新设备 AI 能力静默降级。
- ⚠️ **无数据契约**：`BACKUP_VERSION=3` 但对外未文档化"v1→v2→v3 的破坏性变更"与迁移路径；若未来外部工具（如同学写的解析器）消费该 JSON，版本漂移会成隐患。
- ⚠️ **无资产估值/仪表**：有"资产健康"诊断，但缺少"你已积累多少知识节点/覆盖多少考点/资产增长曲线"的正向激励视图。

### 2.5 项目迭代与技术管理（Iteration & Tech Management）

**评级：A-（迭代纪律强，治理待规范化）**

- ✅ **迭代节奏健康**：git 历史显示清晰的"功能簇"提交（质量地基→AI 卡组→图驱动→自动计划→16 项拓展→不可见算法审计→错误边界→Dashboard→修复连环），每簇目标明确，且**多次出现"fix"回补**，说明有"交付→发现问题→快速修复"的闭环。
- ✅ **关键决策有论证**：从 summary 看，"C 方向（Pinia + Element Plus）"、"同步链路重构"、"打卡纳入同步"等都有权衡记录。
- ✅ **质量内建**：CI 测试门禁 + 错误边界 + 不可见逻辑审计（提交 `79c6ec6`/`#16`）体现"先防错再交付"的工程文化。
- ⚠️ **文档与治理薄弱**：无 LICENSE、无 CHANGELOG、无架构决策记录（ADR）、无贡献指南；`docs/` 偏使用说明，缺"为什么这样设计"的设计文档。
- ⚠️ **安全卫生**：历史对话中曾暴露 GitHub token（已在摘要中提醒撤销）；AI Key 存 `localStorage`（客户端应用可接受，但应明确告知用户密钥在浏览器明文存储、且发往用户自填的第三方端点）。
- ⚠️ **Hub 鉴权薄弱**：局域网中枢用静态 `hub-token.txt` 共享令牌，仅适合受信任局域网，需明确安全边界说明。

## 三、交叉融合总评（Cross-Disciplinary Synthesis）

把四个领域放到一起，会发现三对**结构性张力**，顶级产品的成熟度取决于能否化解它们：

1. **离线优先 ↔ AI 云依赖**：产品以"离线、私有"为信任基石，但 RAG/AI 问答质量依赖远程 embedding/LLM。降级方案（bigram/离线兜底）保住了"可用"，却牺牲了"智能"。**建议对外诚实标注"AI 能力在联网+配Key 时最佳"**，并把"离线优先"严格限定在记忆/复习/统计核心闭环——这恰是用户最在意、也最该零依赖的部分。

2. **功能广度 ↔ 复习专注**：产品管理希望"全链路覆盖"以显专业，学习科学却要求"降低认知负荷、聚焦核心间隔重复"。**解法不是删功能，而是分层**：默认极简复习闭环（加卡/复习/错题），把 Agent/图谱/导图/书房设为"进阶模式"按需展开。Dashboard 应从"炫技数字孪生"回归"下一步该做什么"的行动导向。

3. **数据资产 ↔ 备份脆弱**："本地拥有=资产"是核心理念，但"无自动离设备备份"让资产时刻处于归零风险。**这是理念与落地的根本矛盾**，优先级应高于任何新功能——一个会丢数据的"资产"不是资产。

**一句话总评**：SxyBrick 在"本地优先 + 记忆科学 + 轻 AI + 可移植"这条赛道上，工程完成度与架构成熟度已达**准产品级**，其同步正确性设计（双时间戳字段级合并 + 唯一事实来源）是**可写进教科书**的亮点；但"算法参数未校准、测试覆盖过窄、跨设备同步两处字段遗漏、以及缺失自动离设备备份"四件事，是从"优秀 Demo"迈向"可信赖长期伴侣"必须逾越的门槛。

## 四、风险登记表（Risk Register）

| 编号 | 严重度 | 类别 | 发现 | 代码位置 | 影响 |
|---|---|---|---|---|---|
| **R1** | P0 | 同步正确性 | `wrongReason` 被归入 `CARD_CONTENT_FIELDS`，但复习时由 `review()` 写入且**不 bump `updatedAt`**。另一设备若后续有内容编辑（updatedAt 更新），按内容时间戳合并会**覆盖掉复习写入的错因**，导致错因跨设备静默丢失。 | `sync-manifest.js:34`（内容字段含 wrongReason）；`repo.js:237`（review 写 wrongReason 未 bump updatedAt） | 错题归因在不同设备间不一致，削弱"错因驱动间隔惩罚"与单科诊断的正确性 |

## 六、结论

SxyBrick 已经不是一个"作业级"项目，而是一个**有明确产品哲学、架构纪律与认知科学追求的准产品**。它最值得称道的是：用"同步唯一事实来源 + 双时间戳字段级合并"把分布式同步这件极难的事做对了；用"本地优先"把数据主权还给用户。它最危险的，不是功能不足，而是**两处同步字段遗漏（R1/R2）会让用户以为同步成功实则丢数据**，以及**没有自动离设备备份（R4）让整个"数据资产"悬于浏览器缓存一线**。

从"顶级专家"的尺度看：先堵住 P0 的正确性窟窿与资产安全窟窿，再补测试与性能护栏，最后做产品分层与算法校准——按此顺序，SxyBrick 有资格从"优秀 Demo"晋级为考研生真正敢押注半年的"学习基础设施"。
