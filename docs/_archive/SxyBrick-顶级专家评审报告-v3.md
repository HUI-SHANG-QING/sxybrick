## 2. 七大维度交叉审视（v3 增补）

### 2.1 软件开发 / 工程成熟度
- **改善**：测试从 2→5 份，`crypto.test.mjs`/`sync-export.test.mjs` 覆盖了最易错的同步与加密路径，回归护栏初具规模。
- **风险**：`git status` 显示 **37 个文件未提交**——高速迭代下工作树长期 dirty，既不利于回滚也不利于协作；若一次性大改易引入未受控回归。**强烈建议立即按模块分批提交**。
- **风险**：全仓 0 个 `.ts` 文件，85 个 `.js` 含算法/协议/并发语义，重构时无类型保护，回归风险随规模放大。

### 2.2 架构设计
- **亮点（更成熟）**：同步模型从"双时间戳"进化为**三时间戳分离**（内容 / SRS / 错因各自独立取新者），是分布式合并设计的典范——`mergeCardPair` 的注释把"为什么这么合并"解释得清晰，新人可读。
- **风险**：图谱驱动复习（`getGraphDrivenReviewPlan`）用 **front/back 文本字符串匹配**把图谱节点映射到卡片（`mapLabelsToCards`/`findCardForLabel`）：两张卡 front 相同会被后者静默覆盖；`findCardForLabel` 用 `includes` 可能误匹配。图谱作为"智能编排"中枢，映射健壮性不足可能在千卡规模产生错误的前置/易混建议。

### 2.3 算法 / 学习科学
- **SM-2 变体 + 短期巩固 + 错因枚举惩罚 + 自适应**：算法族完整且方向科学（有 Roediger & Karpicke 2006 依据）。
- **未闭环**：`userOps` 海量行为埋点（v13）仍未反哺算法参数——算法仍是"启发式手调"而非"数据驱动校准"（推荐 FSRS 级别）。埋点与算法两张皮，错失最大差异化机会。

### 2.4 数据资产化（R7′ 最后一公里）
- **已做对**：隐私默认不进同步、本地加密工具就绪——理念领先且合规意识到位。
- **R7′ 残留**：`Export.vue:119-126` 的"人生隐私监控导出"与 opt-in 同步链路，**载荷仍是明文 JSON/CSV**（未调用 `crypto.encryptBackup`）。一旦用户选择同步隐私，局域网 hub 与导出文件均无加密-at-rest/in-transit 保护。这是 PIPL 合规的最后一环，必须补齐。

### 2.5 产品经理视角
- **功能广度已达"学习 OS"级**：数字孪生 Dashboard（首页）、知识图谱、自动计划编排（`generateAutoPlan` 三阶段 + 数据驱动 markdown）、模考、费曼、错题、打卡、周报、成就、资产管家——留存钩子齐备。
- **聚焦问题加剧**：24+ 页面，"什么都做"稀释了"复习内核"这个北极星；建议把差异化从"功能数量"转向"数据飞轮"（埋点→算法→个性化）。

### 2.6 AI 架构师视角
- `agent/` 自研框架（ReAct/流水线/主动智能体/RAG/离线兜底）+ `intelligence.js` + `offlineAI.js` 韧性良好。
- `getModuleSummary` 把跨模块数据蒸馏成 Agent 上下文，设计优雅。
- 工具执行仍阻塞主线程；`embeddings` 同步虽补，但换设备后若未触发重建，`retrieval` 空转——需在 UI 明确"隐私同步开启时自动重建索引"。

### 2.7 迭代方法论（元层面）
- **正向**：单人 3 天 + AI 编辑器产出当前规模，且能把 v2 评审的 P0 落实——证明"AI 原生高速开发 + 强架构纪律"范式成立。
- **隐性债**：广度优先导致"深度负债"——R6（性能）、TS、提交纪律、隐私最后一公里均是被速度牺牲的"正确性/可维护性"。
