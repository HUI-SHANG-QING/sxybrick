## 二、round98 新发现

### R98-1（P3 · P2-1 的会话级残留）长卡详情在「整段会话超 48000 字」时仍被二次砍到约 1500 字

**位置**：`src/agent/agents/base.js:172-199 compactConvo()`，关键在 `:194`
```js
if (over && compressible) {
  if (s.length > 1500) copy.content = clipText(s, 1500) + '…（已截断以控制上下文长度）';
}
```

**成因（两道压缩阀，第二道不认识工具级预算）**：
1. 第一道 `compactToolPayload`（round98 已按工具放宽到 24000）——单条工具结果进上下文时，长卡已能完整保留；
2. 第二道 `compactConvo` 是**整段会话**的总量安全阀（`CONVO_CHAR_BUDGET=48000`）。一旦累计超长，它对**所有**工具观察/助手原文一视同仁，凡 >1500 字一律 `clipText(...,1500)`，**不读取工具声明的 `compact` 预算**。

**实证（fake 数据直跑 compactConvo）**：system 3000 + 6 条 search 观察 + 1 条 `get_card_detail` 长卡（12557 字、含图引用），会话合计 78618 > 48000 → 压缩后长卡那条只剩 **1565 字（正文丢约 88%）**；图片引用因 clipText 挪尾而保住（表现仍为「图在、长文答案被砍」）。

**触发场景（真实可达）**：Agent 一轮里先 `search_cards` 再**连查多张思维导图/错题长卡**，或多轮长对话累积——这恰是用户最需要「长卡完整」的复杂场景。单轮、短历史（会话 <48000，最常见）不受影响，长卡完整。

**影响**：P2-1 在最复杂的多步场景未端到端兑现；但比修复前好（300→1500、图不丢、且该阀是防 413 的必需手段），定 P3（偏高）。

**修复建议**：`compactConvo` 压缩时按工具类型分级——对 `get_card_detail/read_doc/read_note/read_lib_doc` 这类「用户明确要全文」的观察给更高单条保护（如 8000–12000 字），优先压缩 `search_*/list_*` 检索类与更早的历史观察；压缩顺序从旧到新、保住最近一次 detail。可在 `toolObservation` 上携带工具名（已有 `__toolName`，但压缩时被一并删除，可先用于分级再净化）。

### R98-2（P3 · 意图覆盖）高频「学习指导类」泛问题不命中任何模块，也不触发全量 → 零模块明细

**位置**：`src/utils/query-intent.js:10-23`（硬编码关键词表）。

**实证**：`wantedModules` 对「帮我复习一下」「考考我」「我最近学得怎么样」「这张图讲了啥」均返回**空集**（既无模块关键词，也不含「全部/汇总/概览」）→ `buildModuleNodesContext` 直接返回空。

**影响评估（不致命但有体感缺口）**：
- 卡片类问题不受影响——卡片走独立的 `buildQuestionCardContext(text)`（关键词+语义搜卡取全文），不受模块门控；
- 学习概览有兜底——`buildFullContext` 里的 `buildStudyContext`（卡片数/掌握度/薄弱卡 top20/复习建议）**无条件注入**，故「学得怎么样/帮我复习」仍有统计与薄弱卡可答；
- 真正缺的是「最近各模块内容（笔记/文档/单词/计划明细）」；且「这张图讲了啥」不含「笔记/文档/资料」时，文档/笔记里的图不会注入（需用户说「我**笔记**里的图」才命中）。

**修复建议**：把全局学习指导类意图（复习/考一考/抽查/掌握/进度/学得怎样/最近学了啥）映射为「给概览」（返回 null 全量，或显式补一份轻量 stats+最近各模块标题）；把「图/截图/思维导图」纳入 notes+docs+files（卡片图本就由搜卡链路覆盖）。默认策略建议「拿不准就给轻量概览」，避免重新滑向「该看的看不到」。

### R98-3（P3 · 中文化遗漏）笔记分类 category 仍输出英文

**位置**：`src/agent/context.js:226`：`《…》的分类为${n.category || '未分类'}`。notes 的 `category` 取值为 `idea/...` 英文枚举，本轮只映射了 docs.type 与 plans.status，漏了 notes.category。实测输出「分类为idea」。建议补一张 category 中文映射（与 docs.type 同写法）。

### R98-4（P3 · 观察项，非缺陷）总预算 16000 与分项上限不匹配，刹车多数场景不触发

各模块在进总预算前已被单篇 `clipText` 限幅（notes/docs 500、plans 300、memo 200、words 40），单模块上限约 5000–6000 字；实测灌 10 篇×3000 字笔记，注入仅 5344 字、不触顶。粗算只有「全量(null) 且 30 条长备忘 + 近 120 条图谱边 + 大量文档笔记」同时成立（极端约 2.7 万字）才会碰到 16000。`add()` 预算扣减/截断/尾部提示逻辑本身正确，是有效双保险；记录阈值与分项 cap 的量级关系即可，无需紧急改。
