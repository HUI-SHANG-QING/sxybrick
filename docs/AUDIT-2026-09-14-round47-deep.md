## 一、总评（大白话）

这轮查的是"别人能不能骗过你的应用"：恶意内容能不能在页面里执行脚本、导入的脏数据能不能污染库、AI 能不能被骗着删数据、依赖库有没有已知漏洞。

**结论：安全面是这个库工程质量最好的部分之一。零 P0/P1，1 个 P2 已有缓解、1 个 P3 备忘。**

每一块的大白话结论：

- **XSS 面**：全库只有 4 个文件用 `v-html`（绕过 Vue 转义的唯一入口），**逐一核对全部先净化/转义再渲染**。Markdown 渲染有 DOMPurify 白名单净化 + `marked@4` 无内置净化已被补上；Excel/Word 预览这两个经典 XSS 重灾区（外部文档 → HTML）都有 `sanitizeHtml` 把关（代码里有 P0 安全注释）；搜索高亮全部"先转义再高亮"，连单引号属性注入这种细节都在 round15 修过。图片占位符协议（sxy-img://）终点是严格 UUID 正则 + 内存 Map 键控，注入不进去。
- **信任边界**：备份导入有三重前置校验（应用标识 + 范围断言 + 版本闸门），行级合并靠确定性 shape 比对，不盲写；插件系统诚实声明"动态 import 等同 eval、无法真沙箱化"，用"用户主动安装 + 安装提示 + 结构化克隆 + 高危操作二次确认"做风险控制——这是正确的姿态：不假装安全，而是把风险讲清楚。**提示注入防线最扎实**：AI 的 45 个工具里**一个删除/清库类都没有**，就算 AI 被恶意文本骗了，最大破坏也只是覆写一张卡。
- **供应链**：`npm audit` 运行时依赖仅 2 个 moderate（都在 echarts→wordcloud 链，且 echarts 只在 6 个图表组件里渲染本地数据，攻击面几乎为零）；uid 主路径是 `crypto.randomUUID`，randomUUID 不可用的老浏览器兜底在 round23 加固过（时间高位 + 双随机盐）。

## 三、本轮详细发现

### 已核验为「做得对」的安全机制（交叉取证）

| 机制 | 证据位置 | 大白话 |
|---|---|---|
| Markdown 净化 | MarkdownRenderer.vue + `sanitize.js`（DOMPurify 式白名单 + URI 协议正则 + 五字符转义） | 笔记/卡片里的恶意 `<script>`、`onclick=`、`javascript:` 链接进不了 DOM |
| 外部文档预览净化 | `LibraryFiles.vue:255/260`（Excel 表格 HTML、mammoth Word HTML 均过 `sanitizeHtml`，P0 注释在案） | 下载个恶意 Word/Excel 打开预览不会中招——这是很多笔记应用的经典洞 |
| 搜索高亮转义 | `search-service.js:66-74`（round15 P2：五字符含单引号全转义，先转义后 `<mark>` 包裹）；`WordBook.vue:565-575`（词先转义再进正则，正则失败退回纯文本） | 搜索关键词/单词本身是用户输入，不会反向注入 |
| 图片占位符终点安全 | `images.js`：`extractImageIds` 严格 `[0-9a-fA-F-]+` UUID 正则；`imgUrl` 是内存 Map 键控 | `sxy-img://` 后面塞 URL/脚本没有意义，取不出任何东西 |
| 备份导入三重校验 | `sync.js:730-736`：app 标识 !== 'sxybrick' 拒收、`assertBackupScope` 范围断言、版本高于当前拒收 | 伪造/跨库/超前版本的数据包进不来 |
| 插件风险如实声明 | `loader.js:9-14`：明说"动态 import 等同 eval 无法沙箱化"，用主动安装 + 提示 + 结构化克隆 + 高危二次确认控风险 | 不假装能沙箱，把决定权交给用户且挡住自动化攻击路径 |
| 提示注入最小破坏面 | AI 工具全清单 45 个（create/get/generate/list/read 类），**无 delete/clear/reset 类**；写路径仅 `update_card` 覆写 | AI 被注入也只能写/读，删不了任何东西——"最小权限"做在了工具面设计上 |
| 依赖面干净 | 运行时 20 个依赖，npm audit 仅 2 moderate（echarts→wordcloud 链，仅图表渲染本地数据） | 无 known-exploit 高危依赖；wordcloud 是唯一带洞链但攻击面极小 |
| 随机熵达标 | `db.js:429-434`：randomUUID 主路径 + round23 加固兜底（时间高位 + 双 Math.random 盐） | 主键碰撞不构成安全面，跨设备撞 id 概率已被压到工程上可忽略 |

### 发现（无需立即动手）

- **N1 [P3·备忘] `marked@4` 已停止维护**：marked 4.x 系列不再接收安全更新（当前 5.x+ 才是维护线）。实际风险被 DOMPurify 净化层完全覆盖（净化在 HTML 层，不依赖 marked 自身的安全性），所以升级是"卫生"而非"救火"。若未来做依赖批量升级，顺手升到 marked@latest 并跑一遍渲染回归即可。
- **N2 [P3·备忘] echarts→wordcloud 的 moderate 告警**：`npm audit fix --force` 会强升 echarts 大版本（breaking），不建议自动修。wordcloud 渲染的是本地统计数据、无远程输入，实际可利用性趋近于零。等上游 wordcloud 发布兼容新版 echarts 的版本后一并升级。
