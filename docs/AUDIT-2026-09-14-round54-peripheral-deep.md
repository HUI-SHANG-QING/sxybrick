## 🔴 P1

### P1-1　删卡后从回收站还原，**卡里的图片永久丢失**

- **现象（大白话）**：你删了一张带图的卡，后悔了，去回收站点"还原"——**卡回来了，但图全变成空白/破图**，且无法找回。
- **位置**：`src/repo.js:540`（回收站快照字段）＋ `src/repo.js:358-392`（`restoreFromTrash` 还原的表集合）＋ `src/repo.js:606-610`（删卡时物理删图）
- **根因（三条证据链）**：
  1. 删卡时**真的把图删了**：`const orphanImages = await findOrphanImages(imgIds); … await db.images.bulkDelete(orphanImages);`（`repo.js:606-609`）——不再被任何卡引用的图被物理删除 + 写墓碑。
  2. 但回收站快照**不含图片**：`trashItem(id, 'card', { ...old, _reviews, _groupLinks, _cardWordLinks, _cardLinks, _linkedNoteIds })`（`repo.js:540`）——列了 5 类关联数据，**唯独没有 `_images`**。
  3. 还原时**也不还原图**：`restoreFromTrash` 的 `tables` 数组逐个 push 了 reviews/links/docTexts/graphEdges/notes/cards/dailyTasks（`repo.js:366-382`），**没有 `db.images`**。
  → 结果：卡正文里的 `sxy-img://<id>` 占位符还在，但 `db.images` 那行已没，**永久破图**（对端也因墓碑同步删掉了）。
- **建议**：删卡时把该卡引用的图片 blob 一并放进快照（`_images: [{id, blob, mime}]`），还原时回写 `db.images`；
  或对"将被删的图"延迟物理删除（等真正出回收站再删）。**这是"级联删除做了、级联恢复没做"的典型不对称。**

## 🟠 P2

### P2-1　发新版本后，老页面切路由会**白屏**（PWA 经典事故）

- **现象（大白话）**：应用更新了，但页面还开着旧的。这时点菜单/切页面 → 那条路由**空白**，无提示，只能手动刷新。
- **位置**：`src/router.js`（全部 `component: () => import(...)` 懒加载，**无 `router.onError`**）；`src/main.js:21` 全局 error 只 `logError` 不恢复
- **根因**：产物带 hash，发新版后旧 hash chunk 从服务器消失 → 懒加载 `import()` 抛 `ChunkLoadError`/404。
  Vue Router **默认不处理**这种错误 → 组件加载失败就是空白。属 PWA「长驻页面 + 频繁发版」必踩项。
- **建议**：加 `router.onError`，识别 `/ChunkLoadError|Loading chunk|dynamically imported module/` → 提示"应用已更新，正在刷新"并 `location.reload()`（配合已有「有新版本可用」提示）。

### P2-2　复习"专注时长"用**每秒加一**计数 → 切后台/锁屏后严重少算

- **现象（大白话）**：一边复习一边切出去，回来发现"专注时长"只涨了几十秒，实际过了十几分钟；累计进统计就是**偏小的假数字**。
- **位置**：`src/views/Review.vue:549` → `focusTimer = setInterval(() => { focusSeconds.value++; }, 1000);`
- **根因**：把"定时器触发次数"当成"经过时间"。浏览器对**后台标签页定时器会节流**（约 1 次/分钟）→ 每秒 +1 变每分钟 +1；
  而该值还被写进 `localStorage('sxy_rv_focus')` 当**累计**指标。同项目番茄钟/会话计时**已用墙钟**（`endTs`）——同类逻辑两套口径。
- **建议**：改墙钟结算 `Date.now() - startTs`（对"隐藏期间"设计入上限，避免挂机刷时长）。

### P2-3　数据库 34 个版本，**一个数据迁移都没有**

- **现象（大白话）**：现在没事，但意味着"**以后想改字段名/补默认值就没路走**"——老用户升级会拿到缺字段的行，且无处补。
- **位置**：`src/db.js` —— `d.version(N).stores(...)` 共 **34 处**，`.upgrade()` **0 处**（已 grep 确认）
- **根因**：历史版本只做过"加索引/加表"这类纯结构变更（安全），养成"升级回调不需要"的惯性；但导入侧已有"老包缺字段"隐患（见 P2-4），两边都没补齐机制。
- **建议**：约定"改变数据形态的版本必须写 `.upgrade()`"，并在合并/导入入口对缺字段补默认值（双保险）。

### P2-4　导入不是全有全无，失败会留下**半导入**状态

- **现象（大白话）**：导入大包中途存储满了/某图坏了 → **主数据进了、图没进**，一堆破图，且没有"本次导入不完整"的提示。
- **位置**：`src/sync.js:1061`（主事务在此提交）vs `1072-1104`（图片解码+写库）、`1106`（孤儿扫描）、`1130+`（prune）
- **根因**：图片步骤**刻意**拆到事务外（注释写明：避免大事务卡 UI、单张坏图不回滚整 31 表）。属**有理由的权衡**，
  代价是"部分成功"对用户不可见，也没有重试/补导入口。
- **建议**：保留取舍，但把已存在的 `stats.skippedImages` **显式汇报**（"N 张图未导入，可重试"）+ 记错误日志。
  ⚠ 另：`sync.js:735` 版本校验只挡"包版本 > 当前"，对**无 version 的老包**直接放行且无字段迁移 → 建议补 `migrateBackupPayload()`。

### P2-5　质量门禁的"基线"可以被随手一键改掉（闸门形同虚设）

- **现象（大白话）**：i18n 硬编码中文门禁靠一份"基线文件"记账。谁都能跑一条 `--update-baseline` 把**新增违规全认领成"本来就有的"**，闸门永久失效且无人察觉。
- **位置**：`scripts/check-view-i18n.mjs`（`--update-baseline` / `--js-update-baseline`），基线 `scripts/i18n-*-baseline.json`
- **根因**：基线机制只做"比对"，没有**新增数护栏**（如单次新增 > N 行必须人工确认），CI 里也没禁重锚命令。
  ⚠ 配套问题：`tests/vite-glob-guard.test.mjs` 在 dist 不存在时 **`return` 直接 pass**（不是 `todo`），
  而 `npm test` 不含 build → 本地跑测试**永不校验产物**（正是 2026-09-14 线上事故的路径）。
- **建议**：① 基线更新强制输出"本次新增 N 行" + 超阈值直接失败；② CI 禁跑 update 命令；③ 缺产物时改 `t.todo`/显式失败。

## ❌ 经复核后**否决**的 3 条子代理误报（避免误导修复方向）

1. **"预缓存裁掉了入口启动期依赖 → 离线冷启动必崩"** → **不成立**。
   实测构建产物：入口 `index-D5J3weTu.js` 的**静态依赖只有 `element-plus`（1030KB）+ `marked`（37KB），两者都在预缓存**；
   被移出的 956KB `index-B-2YXMQb.js` 经查内容是 **highlight.js**（`new Map` 只读化那段），
   且**只被入口"动态"引用**（代码块才加载）→ 属正确的懒加载裁剪。
2. **"运行时缓存 maxEntries:100 不够，会导致离线失效"** → **不成立**。
   实测：预缓存已收 195 个 assets，`dist/assets` 共 272 文件 / 144 个 js，**仅 9 个 js 未预缓存** → 100 的额度绰绰有余。
3. **"回收站还原引用完整性没问题"**（另一代理的相反结论）→ 与本轮 P1-1 的代码证据链冲突，**采纳 P1-1**。

## 根因归类（三类"外围"通病）

1. **级联删除做了，级联恢复没做** —— 删时把图片/关联都清了，还原时只还原一部分（P1-1）。
   凡"删除带级联"的功能，都必须问一句：**还原能不能把级联过的东西也带回来？**
2. **把"事件次数"当成"经过时间"** —— 秒计数在后台被节流（P2-2）。任何"时长"指标都必须用**墙钟差值**。
3. **闸门的"可绕过性"本身就是缺陷** —— 基线可重锚、产物校验不在默认门禁、缺产物时静默 pass（P2-5）。
   门禁的价值不在"存在"，而在**"改坏东西时一定会红"**。

## 建议修复顺序（按"影响 ÷ 成本"）

1. **P1-1**（回收站还原丢图）—— 真实数据丢失，改动集中在 `repo.js`，收益最高。
2. **P2-1**（chunk 404 白屏）—— 一个 `router.onError` 兜住 PWA 最高频事故。
3. **P2-2**（专注计时失真）—— 改墙钟，几行。
4. **P2-5**（闸门可绕过）—— 关系"质量保障体系"的严肃性，建议同批处理。
5. **P2-3 / P2-4**（迁移通道 + 导入不完整告知）—— 结构性补强，可与下轮功能一起做。
6. **P3 批量**：`beforeunload` 守卫、虚拟列表首帧 observe、死事件清理、OCR 本地语言包。
