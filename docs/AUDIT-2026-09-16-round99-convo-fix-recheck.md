## 二、round99 新发现（均为 P3 · 意图词表精度）

> 都集中在 `src/utils/query-intent.js`。意图门控的失败方向分两种：**误命中**（无关问题被塞学习模块，费 token、轻微干扰）与**漏命中**（该给的没给，重回「看不到」）。

### R99-1（P3 · 误命中，对本用户高频）编程语境的「测试」被当成「复习/测验」

**位置**：`query-intent.js` `REVIEW_RE = /复习|背诵|刷题|练题|考考|测验|测试|默写/`。

**实证**：`wantedModules('怎么写单元测试')`、`('帮我测试这个函数对不对')`、`('测试用例怎么设计')` 均返回 `plans,daily,words`。

**成因/影响**：「测试」是歧义词——学习场景指测验，但本用户是计算机专业（蓝桥杯/全栈/毕设，高频问单元测试、测试用例、测函数），这些问题与学习计划/每日任务/单词毫无关系，却被注入三块学习明细，白耗 token 且可能轻微带偏。方向是「多给」不致命，但对该用户触发率高。

**建议**：REVIEW_RE 去掉裸「测试」，改为无歧义的 `考考我|考一考|考我|小测|测验|自测|抽查|默写|背诵|刷题|练题|复习`；或保留「测试」但要求与「我/一下/学得」共现（如 `测试一下我|测测我`）。

### R99-2（P3 · 漏命中，正对用户核心痛点）图片类问法仍给空集

**实证**：`wantedModules('这张思维导图讲了啥')`、`('这张截图里的公式')` 均返回**空集** → 不注入任何模块明细。

**成因/影响**：上轮 R98-2 已建议把「图/截图/思维导图」纳入，本轮未加。用户贯穿多轮的第一痛点就是「思维导图/错题图片看不到」。卡片里的图走独立的 `buildQuestionCardContext`（按关键词搜卡），但「这张思维导图讲了啥」关键词很难命中卡片正文；**笔记/资料库里的图则因 notes/docs/files 三块都没被意图命中而完全不注入**。

**建议**：新增图片意图，把「图|截图|思维导图|照片|拍照|这张|公式图|导图」映射到 `['notes','docs','files']`（卡片图本就由搜卡链路覆盖）；或在图片词出现时放宽为给这三块明细。

### R99-3（P3 · 误命中，低频）「总结一下我…」对非学习内容误触全量

**位置**：`BROAD_RE = /…|总结一下我|我的学习|…/`。

**实证**：`wantedModules('总结一下我写的这段代码')` → `null`（全量），把全部学习明细发给一个「总结代码」请求。

**成因/影响**：「总结一下我」本意匹配「总结一下我的学习」，但用户可能「总结一下我写的笔记/代码/这段话」。命中概率中低、方向为多给，影响小。

**建议**：把「总结一下我」收紧为「总结一下我(的)?(学习|复习|近况|数据|进度)」，避免「我写的…」误命中。
