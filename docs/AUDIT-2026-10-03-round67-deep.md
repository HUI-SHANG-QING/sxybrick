## 三、新向量：局域网 hub 同步服务端（本维度内零发现）

sync-hub/ 是一台真服务器（手机/平板连电脑同步时的中枢）。逐项核验：

| 防线 | 实现 | 结论 |
|---|---|---|
| **鉴权** | HMAC-SHA256 签名 + `timingSafeEqual` 比较（**防时序攻击**——逐字节比会有毫秒级时差侧信道，恒时比较堵死）+ challenge 一次性（防重放） | ✅ |
| **限流** | 双层限流器：challenge 60 次/分、auth 20 次/分 + 递进锁定（1s→15min）；**限流状态有清理机制**（:433 注释：不释放则泄漏 2 次后所有 PUT 恒 429——已防） | ✅ |
| **请求体上限** | 50MB 硬限，超限直接断连接（:439）——防"一个巨大请求吃光内存" | ✅ |
| **并发正确性** | per-scope 串行队列（B8）：两台设备同时 PUT 同一份数据不会互相踩踏；Windows 文件占用（EBUSY）有重试通道（round34 P1-1：读失败≠数据损坏，不会把中枢清零） | ✅ |
| **时钟偏移** | `clockSkew` 从请求头取客户端与中枢的钟差，合并时扣减（round48 同款纪律在服务端也生效） | ✅ |
| **墓碑卫生** | 中枢侧失效墓碑不常驻回灌（:346 注释：此前只取 rows 不清 stale，垃圾每次同步都发给所有客户端——已修） | ✅ |
| **静态服务防路径穿越** | `hub.js:550`：路径 normalize 后必须落在 dist 目录内（`!p.startsWith(DIST + sep)` 回退 index.html）——`../../etc/passwd` 这种穿越拿不到东西 | ✅ |

**大白话总结**：这台小服务器的安全配置是按"真服务器"标准写的——恒时比较、一次性口令、限流递进锁定、并发排队、路径穿越防护，一个不缺。之前审计一直没碰它，这次查完可以放心：**局域网同步的中枢不是裸奔的，是带门禁的。**
