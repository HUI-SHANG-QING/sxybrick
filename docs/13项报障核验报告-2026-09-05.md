## 二、已修项的关键证据

### 热力图（#1/#8）
根因：`series` 格子 x 坐标是**列号字符串**（`'0'..'52'`），而 `xAxis.data` 原填**月份名**，
category 轴下两者永不匹配 → ECharts 匹配不上 → 格子全不渲染。
修复：`xAxis.data` 改为列号数组，月份标签交给 `axisLabel.formatter` 按列索引查表。

全项目共 3 处 heatmap，另两处坐标本就一致，无需改动：
- `Stats.vue:102` 日历坐标系
- `UserDashboard.vue:368` 168h 热力（`xAxis` 与 `series` 同为 `HH:00` 格式）

### Agent TDZ（#5）
- `a0ae750` 断开 `offlineAI ↔ genDeck` 双向 import 环
- `9b34cae` 新增 `scripts/dep-check.mjs` 把循环依赖检查**左移到提交前**
- 实测：`node scripts/dep-check.mjs` → **256 源文件、0 环、0 未解析**
- `PRESET_PIPELINES` 声明（`pipeline.js:35`）先于全部使用（L77+），无同级 TDZ

> ⚠️ TDZ 的特性是 **node 下全绿、打包提升后才崩**。若你仍复现，请先确认跑的是
> `c1e4ef1` 之后的构建（旧 bundle 会一直报同一个错）。

### 卡组新建无反应（#12）
根因：`editing = null` 同时表示「新建」和「不在编辑中」，`v-if="editing !== null"` 判为假 → 表单永不显示。
修复：新增独立 `showForm` 开关（`CardGroups.vue` L48 声明 / L65-66 开启 / L148 渲染）。

### 桑基图（#4/#7）
- 规模防护：节点 >120 或边 >240 降级力导向，防 ECharts 崩溃糊成黑块（`e1fc3f4`）

### ⚠️ 两处需你决策

**1. `trash`（回收站）被有意排除** —— 与你「回收站也要同步」的诉求冲突

排除理由（源码注释）：删除语义由**墓碑**表达，回收站快照仅本机恢复用。
若开放同步会与墓碑复活判定打架：对端从回收站恢复一张卡，而本端墓碑认为它已删 → 语义冲突。
要支持需先定规则（例如「恢复 = 写一条更新的复活时间戳并清墓碑」）。

**2. `meta` 表只同步 `goal` 一个键**

`meta` 不走 `SYNC_TABLES`，而是经 `backup.streakMeta` 只同步打卡目标。
**其余 meta 键跨设备不同步** —— 这是真实缺口，新 meta 数据不能指望自动同步。
