## 二、逐条根因分析

### B1 · 「12 点」的语境分裂（P2）

**代码**（修复前）：

```js
let h = parseInt(m[1], 10);
if (/(下午|傍晚|晚上|晚|pm)/i.test(s) && h <= 12) h += 12;   // ← 12 也进 +12
if (h >= 0 && h <= 23) return h;                             // ← 24 越界 → 整条丢弃
```

**根因**：12 小时制里 `12` 是唯一"不加 12"的例外（12 AM = 0 点 / 12 PM = 12 点）。
代码写成 `h <= 12` 统一加 12，于是 `12 + 12 = 24` 被出口的 `h <= 23` 丢弃。

**关键点**：出口丢弃**不是报错，而是静默落到下方的"时段关键词粗映射"**：

| 输入 | 中间态 | 出口 | 落到关键词 | 实际返回 | 正确 |
|---|---|---|---|---|---|
| 晚上12点 | 24 | 丢弃 | `晚上 → 19` | **19** | 0 |
| 下午12点 | 24 | 丢弃 | `下午 → 14` | **14** | 12 |
| 凌晨12点 | 12 | 通过 | — | **12** | 0 |

这条"丢弃后兜底"的路径让错误看起来像是"正常地走了粗映射"。

**为什么潜伏**：`extractHour` **此前完全没有测试覆盖**（`grep extractHour tests/*.mjs` = 0 命中）。

**修法**：拆出 `toHour24(h12, s)`，把**夜间向**与**下午侧**分开定义——
中文口语里"12 点"指向哪一端由时段前缀的语义方向决定，不能靠 AM/PM 二分：

```js
const NIGHT_RE = /(凌晨|深夜|夜里|今夜|夜晚|晚间|晚上|晚)/;
const PM_RE    = /(中午|正午|晌午|下午|傍晚|晚上|晚间|夜晚|夜里|今夜|pm|晚)/i;
function toHour24(h12, s) {
  if (h12 === 12) return NIGHT_RE.test(s) ? 0 : 12;   // 夜间 = 午夜 / 其余 = 正午
  if (h12 >= 1 && h12 <= 11) return PM_RE.test(s) ? h12 + 12 : h12;
  return h12;                                          // 13..23 是 24 小时制，原样放行
}
```

**修复中的两次返工（已记入测试注释）**：
1. 第一版用 `AM_RE && !PM_RE` 判 12 点 → `下午12点` 正确但 `晚上12点` 仍错（"晚"在 PM_RE 里）→ 改为按**夜间/正午**拆。
2. 第一版让 `toHour24` 对 `>12` 返回 `null` → **`14:30` / `14点30分` 回归成 null**（24 小时制被 12 小时制逻辑吃掉）→ 改为原样放行。
3. 引入 `NIGHT_RE` 当"下午侧"判据 → **`凌晨1点` 变成 13 点** → 拆成 `NIGHT_RE`（仅用于 12 点档）与 `PM_RE`（用于 1..11 档）。

### B2 · 负向断言误杀中文单位（P2）

**代码**（修复前）：

```js
const timeRe = /(\d+(?:\.\d+)?)\s*(分钟|min|mins|小时|hours?|h)(?![a-z\u4e00-\u9fff])/gi;
//                                                            ^^^^^^^^^^^^^^^^^^^ 中文也被禁区
```

**根因**：挂这条负向断言的**本意**是防单字母 `h` 误匹配英文单词。但它作用于**整个单位组**，
于是中文单位 `分钟`/`小时` 后面也不能跟中文：

| 输入 | 匹配 | 原因 |
|---|---|---|
| `学100分钟` | ✅ | `分钟` 后是串尾 |
| `130分钟数学` | ❌ | `分钟` 后跟中文"数学" |
| `做2小时数学` | ❌ | `小时` 后跟中文"数学" |
| `背30分钟单词` | ❌ | `分钟` 后跟中文"单词" |

**而「数字 + 小时/分钟 + 紧接着科目名」恰是中文计划文本最主流的写法**。

**下游后果不是"少个字段"**：`planCharts.js:407` 用 `estimatedMinutes` 算课程表格子高度
（`fmtHour(it.task.scheduledHour + (it.task.estimatedMinutes || defaultDur) / 60)`），
丢时长 → 退回 `defaultDur` → 全天安排的时长估算系统性失真。

**修法**：只给**英文缩写**加边界（只有英文有词边界问题），中文单位直接放行：

```js
const timeRe = /(\d+(?:\.\d+)?)\s*(分钟|小时|(?<![a-z])(?:mins?|hours?|h)(?![a-z]))/gi;
```

### B3 · 四象限忽略否定词（P2）

**代码**：全是 `s.includes(w)` 字面包含。

`Q2_WORDS` 含 `重要`，`Q3_WORDS` 含 `急`。用户写「很重要但**不**急」：
- `重要` 命中 Q2 → `important = true`
- `急` 命中 Q3 → `urgent = true`（**"不急"里的"急"被当成"急"**）
- → **Q1（最优先）**

实测全部误判为 Q1：`很重要但不急的复习` / `不紧急但要完成` / `重要的英语不急` / `重要的错题不急着做`。

**为什么要紧**：四象限是每日规划的主视图，把"不紧急"排到第一优先级**直接误导用户先做次要的事**——
这与用户既有的"监督力效率"设计原则（损失必须明确量化、不能 over-nudge）方向相反。

**修法**：先用正则把「否定词 + 0~2 字 + 紧急/重要词」整段**打码成等长空格**，再跑关键词：

```js
const NEG = '(?:不|别|无需|无须|不用|不必|勿|免|没有|没)';
const negRe = new RegExp(`${NEG}.{0,2}?(?:紧急|急|尽快|快|来不及|赶|重要|关键|核心|重点|优先)`, 'g');
function maskNegated(s) { return s.replace(negRe, (m) => ' '.repeat(m.length)); }
```

- **打码而非删除**：避免删除后相邻词被错误拼接产生新的假匹配。
- **限制 0~2 字间隔**：避免"不重要的内容，但这事很紧急"这类**跨小句**的否定误伤后半句。

### B4 · 提醒窗口的提前量跨午夜失效（P3）

**代码**（修复前）：`const due = t.scheduledHour * 60 - (advanceMin || 0);`
`curMin` 只有 `0..1439`。`0 点 + 提前 10` → `due = -10` → 窗口 `[-10, 5)`
→ 只在**当天 00:00~00:05** 成立。用户设的"提前 10 分钟"本意是**前一天 23:50**。

**另有调用侧问题**：`startReminderScheduler` 只 `where('date').equals(today)`，
23:50 那刻 `today` 是前一天，**根本查不到次日 0 点的任务**。

**修法**（两处）：
1. `dueTasksOf`：窗口按 `1440` 取模，**跨日时两段取并集**：
   ```js
   const lo = ((due % DAY_MIN) + DAY_MIN) % DAY_MIN;
   const end = lo + WINDOW;
   return end <= DAY_MIN ? (curMin >= lo && curMin < end)
                         : (curMin >= lo || curMin < end - DAY_MIN);
   ```
2. tick：`advanceMin > 0` 时把**明天**的 plan 一起查出来（今天是 D-1，要在 23:50 提醒 D 日 0 点的任务）。

**修复中的返工**：我先做「单向回绕」（`due += 1440`），只补上 23:50~23:59 那半段，
**丢掉了 00:00~00:04 那截**（实测 `00:04` 不命中）→ 改为两段并集。
另补一处护栏：越界 `hour=25` 经取模会变成"1 点提醒"——**凭空造出一个用户没排过的提醒**，
故新增 `h < 0 || h > 23` 直接不提醒。

### B5 · 考研高频量词漏检（P3）

量词表缺 `道/讲/问/段/集/课`。其中 **`道` 是理科刷题最标准的量词**（"做8道题"、"刷120道"）。
丢失 `targetCount` → `planSynergy.js:217-222` 的 `planByType.review += t.targetCount || 0` 少算规划总量。

### B6 · 去重键只写不删（P3）

`sxy_plan_reminded_<date>_<taskId>` 全项目 `removeItem` 计数 = **0**。
注释说"次日自动失效"——那是**语义上**失效（换日期就查不到），**键本身永久残留**。
实测：每天 8 任务 × 51 字符 ≈ 148KB/年，5 年 ~0.72MB。量级不大，但属"只写不删"模式：
localStorage 写满后**所有**写入静默失败，会连累项目其它关键开关
（`sxy_privacy_sync`、`sxy_heal_broken_dueat_v1`、`sxy_tel_*` 等）。
