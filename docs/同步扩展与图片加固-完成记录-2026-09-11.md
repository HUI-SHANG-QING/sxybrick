经用户确认，以下 3 张表**继续保持本机、不参与同步**；`EXCLUDED_FROM_SYNC` 维持
`snapshots / plugins / docTexts / docBlobs / trash / imageRefs`（6 张）。障碍与理由：

| 表 | 障碍（实测） | 结论 |
|---|---|---|
| **snapshots** | `saveSnapshot` 把**全库所有表 + 墓碑 + 元数据**塞进一行（`rows[t.table]=arr`，含 `sizeBytes`）。同步 N 份 = **N× 整库体积** → 中枢/包体爆炸；且快照仅本机回滚用 | 保持本机 |
| **plugins** | 插件以 **ES Module 代码字符串**存库（`plugins/manifest.js`），运行时动态 import。同步＝**执行外来代码**；代码/配置可能含硬编码 API Key | 保持本机 |
| **trash** | 回收站快照与**墓碑删除语义冲突**：A 删除（墓碑）→ B 从其回收站恢复 → A 的墓碑再次删除 → 反复 | 保持本机 |

## 三、语义提醒（已同步机制下的注意事项）

- **wordStudyLog 是按日累加**（`id=t-YYYY-MM-DD`，`ms += delta`）。idOnly 下同一天两端的时长**不会相加**（本地已有行胜出）——不会虚增，但也不是求和。若要跨设备**求和**，需把 id 改为「按设备分片」再聚合。
- **notifications 已读状态按设备本地**：通知本体跨设备同步，但在一台设备上标记已读不会同步到另一台（idOnly 不传播已存在行的更新）。如需同步已读态，需改为 `updatedAt` 策略并在标记已读时 bump 时间戳。
- **errors/aiUsage/wordExportHistory 有本机容量上限**（errors ≤200 条、导出历史 ≤30 条且近一年），超限清理会写墓碑同步删除——属预期行为，但会在设备间产生少量墓碑流量。
