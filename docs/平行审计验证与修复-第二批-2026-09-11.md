## 一、严重项

### ① 英语学习时长跨设备会丢 —— 属实，已修
**根因**：两端同一天用**同一个行 id** `t-<YYYY-MM-DD>`，`wordStudyLog` 走 idOnly 合并 → "已存在则保留本地" → 手机 30min 同步到平板时被平板本地的 20min 挡住；反过来同理。结果：**一端时长丢失，且两台永久不一致**（A 显示 30、B 显示 20）。

**修法（按设备分片 + 求和，既不丢也不虚增）**：
- 写入：`id = t-<date>-<deviceId>`，`deviceId` 懒生成存 `db.meta`（**不参与同步**，各设备独立）。
- 读取：今日 = 按 `date` 索引汇总所有设备行；累计 = 全表求和 → **手机 30min + 平板 20min = 50min**。
- 幂等：重复合并/重复读取不改变结果（行之间互不覆盖）。
- 兼容：旧格式行 `t-<date>` 带 `date` 字段，一并汇总；且**不会双计**——旧行是"升级前累计"、新行是"升级后增量"，两者时间上不重叠。

### ② 通知"已读"不同步 + 删除不写墓碑 —— 属实，已修
**根因**（`src/agent/proactive.js` 共 5 处写路径）：
- `markRead`：`update(id,{read:1})` 不 bump `updatedAt` → idOnly 下"已存在行"的更新**不传播** → 手机点已读、平板红点照旧。
- `markAllRead`：同上（bulkPut read:1，无时间戳变化）。
- 超量清理 `bulkDelete` / `clearAllNotifications`（`clear`）/ `deleteNotification`（`delete`）**都没写墓碑** → 对端持有的旧副本下次同步**复活**。

**修法**：
- `notifications` 合并策略 `idOnly` → **`updatedAt`**（内容不可变、只有 `read` 变，LWW 足够且收敛）。
- 读操作统一 bump `updatedAt`（`markRead` / `markAllRead`）；创建时也带 `updatedAt` 作为 LWW 基准。
- 三处删除全部写墓碑 `kind='notification'`（并置于事务内，与行删除同生共死）。

### ③ 产品决策：已读语义取**全局**（② 的前提）
按你描述的现象（"手机上点了已读，平板上还亮着红点"＝不满），确定为**全局已读**：一处已读 → 处处已读。
> 若你更想要"各看各的"（每台设备独立已读），那 ② 的修法应反过来：把 `notifications` 排除出同步、已读仅本地。告诉我就改。
