# round29：手机端「检索失败」与「答错次数不跨设备」缺陷分析

> 日期：2026-09-08 · 触发：用户实测反馈（手机端「我的卡片」检索失败 + 红色「答错 N 次」只在手机端出现）
> 结论：两个都不是同步 bug，而是**本地状态/派生数据的可见性缺陷**，但表现极具迷惑性（看起来像同步丢数据）。
> commit：`08282f8`（本地已落，push 因网络失败待用户终端执行）

## 一、问题清单与根因

| 编号 | 严重度 | 位置 | 缺陷 | 根因 |
|---|---|---|---|---|
| BUG-A | P0 | `src/views/Cards.vue` 搜索词状态 | 「我的卡片」检索失败，强制刷新无效，换浏览器正常 | 搜索词存在**两个互不同步的 localStorage 源** |
| BUG-B | P1 | `src/views/Cards.vue` 红标 + `failCount` 语义 | 红色「答错 N 次」只在手机端出现 | ①红标依赖**本地开关** `weakMode`；②`failCount` 是**派生值**，此前只在「错题集」模式计算 |
| BUG-C | P2 | `src/views/Cards.vue` filters 解析 | 坏 localStorage 值可让组件 setup 抛错（白屏）或筛选静默失效 | `JSON.parse` 无兜底、无字段白名单 |

### BUG-A 根因详解（为什么"强制刷新无效、换浏览器就好"）

```js
// 修复前：两个独立的持久化源
const filters     = reactive(JSON.parse(localStorage.getItem('sxy_card_filters') || '...')); // 含 q
const searchInput = ref(localStorage.getItem('sxy_card_search') || '');                       // 也有 q
watch(searchInput, v => { setTimeout(() => { filters.q = v.trim(); }, 300);
                          localStorage.setItem('sxy_card_search', v); });
watch(() => [filters.subject, filters.logic], saveCardFilters); // ← q 变化时【不落盘】
```

- `sxy_card_search` 每次输入都写；`sxy_card_filters.q` 只在 subject/tags/logic 变动时**顺带**写入。
- 于是刷新后：输入框显示上次搜的词 A，而 `filters.q` 是更早某个时刻写入的 B → **列表按 B 过滤**。
- 更致命：`watch(searchInput)` 只在**值变化**时触发。用户看到框里已有词、不再改动 → watch 永不触发 → `filters.q` 永远是 B。重新输入**同一个词**也不触发。
- → 表现为"检索失败"；强制刷新无用（坏状态被 localStorage 恢复）；换浏览器 localStorage 干净 → 正常。

### BUG-B 根因详解

```vue
<span v-if="weakMode && item.failCount" style="background:var(--red)">答错{{item.failCount}}次</span>
```

1. `weakMode` = 「错题集」开关，存 `localStorage['sxy_card_weak']` —— **纯本地视图偏好，不参与任何同步**
   （`SYNC_TABLES` 里没有它，也不该有：它控制的是"列表只列错题"，属视图）。
2. `failCount` **不是卡片持久字段**，而是 `reviews` 流水实时聚合（`repo-core.rankWeakCards`，只统计 `rating === 0`），
   此前**只有「错题集」模式会算** → 没开该开关的设备拿到的行里根本没有 `failCount`。
3. 叠加效果：手机开了「错题集」→ 有红标；电脑/平板没开 → 列表全量、零红标。用户据此判断"同步丢了数据"。

## 二、修复内容

| 编号 | 修复 |
|---|---|
| BUG-A | 单一数据源：`filters.q` 为唯一权威值，`searchInput` 仅作输入镜像；初始化同源；`q` 变化纳入落盘；输入框加 `@keyup.enter` 立即生效（移动端中文输入法兜底）；清理历史遗留 key `sxy_card_search` |
| BUG-B | ①红标条件 `weakMode && item.failCount` → `item.failCount`（「错题集」开关回归其本职：只负责筛选）；②新增 `repo.failCountMap()`（cardId → 答错次数），`loadCards` 统一附加，所有模式/设备一致 |
| BUG-C | 新增 `normalizeFilters()`：try/catch + 字段白名单归一化，坏值退回默认而不是崩渲染 |

**`failCountMap()` 性能设计**：列表每次搜索都全表扫描 `reviews`（万级流水约百毫秒）不可接受，
故用「`reviews` 行数 + 最新 `reviewedAt`」组成轻量 key 做缓存 —— 复习/清理必然改变其一，命中时零扫描。

## 五、第二轮：`c.failCount` 直读统一收敛（commit `9baa8d7`）

第一轮留下的问题：`failCount` 是派生值，**数据源带不带这个字段全凭运气**——
`weakCards()` 出来的带，`db.cards.bulkGet / listCards / toArray` 出来的不带。
后者直读 `c.failCount` 恒为 `undefined`，而且是**静默失效**（有 `|| 0` 兜底的地方不报错，只是功能永远不触发）。

### 逐处判定结果

| 位置 | 数据源 | 判定 |
|---|---|---|
| `agent/context.js:51`、`agent/proactive.js:169` | `weakCards()` | ✅ 安全，不动 |
| `agent/tools/index.js:78`、`:603` | `weakCards()` | ✅ 安全，不动 |
| `agent/analytics.js` weakList（`_generateAutoPlan`） | `weakCards(20,1)` | ✅ 安全，不动 |
| `intelligence.js:824`、`views/WrongBook.vue`、`views/Dashboard.vue:231` | `weakCards()` | ✅ 安全，不动 |
| `agent/analytics.js`（`_getGraphDrivenReviewPlan`） | `cards.filter(...)` 派生 | ❌ 缺字段 → 注入 |
| `views/CardLinkAnalysis.vue` → `ai-analyzer.cardBriefer` | `db.cards.bulkGet` / `listCards` | ❌ 缺字段，**AI 的「薄弱(错N次)」标记永不出现** |
| `views/CardLinkAnalysis.vue` → `local-analyzer.learningPath` | 同上 | ❌ 缺字段，**「薄弱优先」排序退化为只看 `ease<2.2`** |

### 收敛方式

新增 **唯一入口** `repo.attachFailCounts(cards)`（内部走带缓存的 `failCountMap`）：
无失败记录的行**保持原对象引用**（零拷贝），聚合失败**原样返回**绝不阻断调用方。
在三个数据出口统一注入：`Cards.vue` 列表、`CardLinkAnalysis.vue` 分析入口、`analytics.js` 的 weak 派生。

**关键取舍**：`ai-analyzer.js` / `local-analyzer.js` 是纯算法模块（被测试直接 import），
没有让它们 import `repo.js` 依赖 db，而是在**唯一的调用入口注入**——保持算法层无 IO 依赖。

## 六、遗留

1. **「错题集」开关仍为本地偏好**（设计如此，与"视图模式/排序"同类）。修复后它只影响"只列错题"，
   不再影响答错次数的可见性，跨设备困惑应消除。
2. 若某设备仍看不到答错次数，检查方向应是：`reviews` 表是否随数据包一起导入
   （完整备份包含 `reviews`；若只导"卡片 JSON 包"则不含复习流水 → 必然算不出次数）。
3. 后续若新增卡片字段，凡"由流水聚合而来"的（如未来可能加的最近正确率、连续答对次数），
   都应走 `attach*` 入口在数据出口注入，不要让消费方直读——否则复现同一类静默失效。
