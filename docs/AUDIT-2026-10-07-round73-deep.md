## 四、主攻：攻克第二个静态盲区——quick-check 快速校验全链（本维度内零发现）

round71 用 grep 定位失败的模块，这轮直接读完全部 168 行（`src/utils/quickCheck.js`）。这是 round118/122/127 多轮修复的聚集地，专查"修 A 破 B"：

### 窗口语义（核心状态机）

- **锚点设计**（quickAnchorOf）：默认锚点 = reviewedAt（最近复习）；**绝不篡改 reviewedAt 本身**——注释写明它是 SRS 核心字段（FSRS 间隔/跨设备竞争/统计都依赖），动它会污染排期与同步
- **窗口判定**（isQuickDue）：level≤1 + 距锚点 10min~1h + 本周期未校验过（quickCheckedAt > 锚点才跳过）——纯函数、可测
- **跳过两段式**（skipDecision）：首跳把锚点推到"距过期仅 1 分钟"（最多再弹 1 次）；第二跳写 quickCheckedAt 彻底放弃。注释解释了为什么必须有终止标记：窗口是硬区间，任何不跨过 60min 的推迟都会被下次轮询继续命中

### "修 A 破 B"复查（历轮修复互不打架）

| 历轮修复 | 本轮复查 | 结论 |
|---|---|---|
| round118 锚点重置/跳过顺延 | 锚点独立于 reviewedAt（fieldTs 记录）、两段式有终止标记 | ✅ 语义自洽 |
| round122 改走共享快照 + 去掉 dueAt 预筛 | 注释里留了完整因果：旧预筛隐含"level≤1 必在 1 天内到期"——该假设只在 SM-2 成立，**FSRS 下 level=1 的卡间隔 1.1~3.4 天，该弹的卡永远捞不到且无报错**（功能静默失效）。改走快照后不依赖任何排期假设，且零额外全表读 | ✅ 且是"假设被实测推翻"的又一案例 |
| round57 只读契约 | 注释明示"快照数组只能 filter 产新数组再 sort，绝不能原地 sort/push"（快照 key 不含内容，污染不自愈） | ✅ 契约遵守 |
| 单次上限 | `slice(0, 8)` 防疲劳 | ✅ |
| 写路径失效 | skipQuickCheck/recordQuickCheck 末尾都显式 `invalidateDashboardCache()`——注释点出例外场景："同一毫秒连续跳过两张卡，第二次的 updatedAt 与最大值相同 → 快照 key 全不变 → 命中陈旧快照"，**把这个例外显式封死** | ✅ |

### 记录事务原子性

`recordQuickCheck`：校验记录与卡片标记**同事务**（否则配额满时记录落了、标记没落 → 重复弹）；卡更新走**差量写**（B11 改造最后漏网点）；卡不存在则连记录都不写（防孤儿 reviews）。

**大白话总结**：这个模块是历轮修复的十字路口（锚点、快照、差量写、墓碑外的第四种纪律——显式失效），但每条修复都留了注释写清"为什么"，且互不踩脚。**修 A 破 B 在这里没有发生。**
