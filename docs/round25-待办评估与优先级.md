## 二、逐条详情（原因 / 影响 / 不修风险 / 方案）

### U-1 搜索无防抖 —— 必须修复
- 原因：`WordPhrases.vue:47` `watch(q, load)` 无防抖，`load()` 内部 `listWordCards` 全表读取+内存过滤。
- 影响：每敲一个字符触发一次全表扫描；词库 5000+ 时输入明显卡顿（移动端更糟）。
- 不修风险：输入体验差、主线程占用高，可能连带影响复习页流畅度。
- 方案：`watch(q, debounce(load, 200))`（项目已有 `src/utils/` 可加 `debounce`）；`filterKind` 切换保持即时。

### A-3 播种对巩固期卡不准 —— 建议修复
- 原因：存量卡首次切 FSRS 时按"首次评级"播种 S（again→0.25 天），未利用已有复习历史/间隔。
- 影响：切换调度器后间隔被压到 0.25 天，需要多背数轮才恢复到应有间隔。
- 不修风险：用户切 FSRS 后体感"越背越差"，可能误判算法有问题。
- 方案：播种时若卡已有 `reviewedAt/intervalDays`，用现有间隔反解初始 S（或用 `intervalDays` 做下限），几行改动 + 单测。

### D-5 dueWordCards 全表扫描 —— 建议修复（看规模）
- 原因：`word-repo.js:444` `let rows = await db.wordCards.toArray()` 再内存过滤到期。
- 影响：每次进复习页全表读；1000 词无感，5000+ 词明显卡顿。
- 方案：`db.wordCards.where('dueAt').belowOrEqual(now).toArray()` 先索引收窄，再按 kind/停车过滤（与通用卡 `reviewQueue` 已做的收窄对齐）。

### U-2 连点"加入" —— 建议修复
- 原因：`WordBook.vue:132-140 addWord` 无 `adding` 防重入；`isAdded` 在首次点击后立即更新（多数场景兜住），但同一 tick 内双击仍有窗口。
- 方案：加 `addingWord` ref 防重入（与 `saving` 同款），按钮 `:disabled="addingWord || isAdded(w)"`。

### ① 删除路径四件套 helper —— 建议修复（中等，非紧急）
- 原因：`deleteCard / deleteWordCard / deleteWordGroup / deleteCardGroup / 清空…` 各自重复"快照→墓碑→删关联→删主记录"。
- 不修风险：新增表时漏改某条路径 → 悬空行或恢复后关联丢失（此前 B1 就是此类）。
- 方案：抽 `trashDelete({ kind, id, tables })` 统一 4 步 + `restore()` 对称分支；由 schema 元数据驱动快照内容。

### U-3 批量建卡无事务 —— 可暂缓
- 现状：`WordBook.vue:144-149` 循环 `createWordCard` 无事务；但 `addPage` 每次以 `!isAdded(w)` 计算待加集合，中断重试会跳过已加的。
- 结论：非原子但**基本自愈**，风险低于同类问题；建议与 U-2 一起顺手包一层 `db.transaction`。

### A-7 / A-11 —— 低优先
- A-7：`computeNext(card, rating, intensity, guessed, opts)` 内部取 `Date.now()`；加 `opts.now` 默认值即可解锁时间旅行测试。
- A-11：仅 rating=1 档校准与训练口径相反；影响页面观感，可随校准面板改版一并处理。

### 无需处理（判断依据）
- **A-2**：`fsrs.js:226-233` 已 `w0[17]=0` 消噪训练、`fsrs.js:317` 恢复 fuzz——清单基于旧代码。
- **A-4/A-5**：设计如此且默认用户不触达；`srs.js:222` 已注明乘子与 intensity 正交。
- **A-9**：`w[17]` 是 fuzz 且已消费；末位即使未用，对结果影响可忽略。
- **S-11**：中枢程序不在本仓库，无法评估；需在中枢侧单独看。
